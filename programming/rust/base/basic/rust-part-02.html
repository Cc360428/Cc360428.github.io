所有权、借用与生命周期 ​

读下面的签名时先标出数据的拥有者和最后一个读者。想独立观察借出的子串为何会阻止原字符串被清空，可以把所有权与返回引用实验单独编译，比较成功与 E0502 两种结果。

移动、复制与释放 ​

先观察类型和函数签名，再判断所有权。String 拥有可增长的字符串数据；把它赋值给新变量或按值传给函数会移动所有权。移动后原绑定不能继续使用。i32 等实现 Copy 的类型在赋值时复制；是否 Copy 由类型决定，不能仅凭“在栈上还是在堆上”判断。官方所有权章节解释了移动与 clone 的区别。

String::from("rust") 调用关联函数，从字符串字面量创建一个拥有数据的 String；text.len() 是在值上调用方法，这里的结果是字节数。

rust
fn consume(text: String) -> usize {
    text.len()
} // text 在这里释放其拥有的资源

fn main() {
    let first = String::from("rust");
    let second = first;
    // println!("{first}"); // 取消注释后应产生“使用已移动的值”错误
    assert_eq!(consume(second), 4);

    let count = 3;
    let copied = count;
    assert_eq!(count + copied, 6);
}

需要两份独立的 String 时显式调用 clone()，它会复制字符串数据。不要只为消除借用报错而到处克隆：先检查函数是否只需读取。如果拥有者正常离开作用域且值尚未被移走，Rust 会清理该值拥有的资源；Drop 是资源管理的一部分，不只用于内存。

通过引用读取与修改 ​

&T 共享借用，&mut T 独占可变借用。对同一数据的重叠访问，需要遵守多个共享借用与一个独占可变借用之间的约束；引用还必须指向有效数据。普通读取接口通常接收 &str、&[T]，这样既能接收拥有者的借用，也能接收子区间。引用与借用给出了规则与编译器诊断。

下例的 split_whitespace().count() 先按空白分词，再统计词数；迭代器的组合用法在集合一节展开。

rust
fn word_count(text: &str) -> usize {
    text.split_whitespace().count()
}

fn append_mark(text: &mut String) {
    text.push('!');
}

fn main() {
    let mut message = String::from("hello rust");
    let view = &message;
    assert_eq!(word_count(view), 2); // view 的最后一次使用
    append_mark(&mut message);
    assert_eq!(message, "hello rust!");
}

借用通常可以在最后一次使用之后结束，不一定持续到外层 }。旧译文中“必须加大括号才能结束借用”的判断不能直接套到现行代码。反过来，如果把 view 的使用移到 append_mark 后面，共享借用与可变借用发生冲突，应该重新安排读取和修改的顺序。

&mut T 允许修改引用指向的数据；持有这个引用的绑定本身不需要写 mut，除非需要给该绑定重新赋值。需要直接读取或修改所指的值时，使用解引用运算符 *，例如后文的 *score += 1。安全 Rust 还提供 Cell、RefCell 等内部可变性工具；这些工具有各自的约束，不属于初学时绕过借用检查的通用办法。

切片与生命周期 ​

[T] 是切片类型，T 在这里代表元素类型；常用 &[T] 或 &mut [T] 借用连续元素。长度在运行时携带，可变切片允许修改元素，但不能借它给原集合增删元素。数组能借出切片，后文的动态数组 Vec 也可以，数据不因借用而复制。切片章节说明了这种接口。

rust
fn reset_first(values: &mut [i32]) {
    if !values.is_empty() {
        values[0] = 0;
    }
}

fn main() {
    let mut values = [4, 5, 6];
    reset_first(&mut values[..2]);
    assert_eq!(values, [0, 5, 6]);
    reset_first(&mut []); // 空切片也应能安全处理
}

生命周期注解描述引用之间的有效期关系，不会延长数据存活时间。一个输入引用对应一个输出引用时通常可省略；多个输入引用、返回值可能来自其中任意一个时，需要明确约束。

rust
fn longer<'a>(left: &'a str, right: &'a str) -> &'a str {
    if left.len() >= right.len() { left } else { right }
}

fn main() {
    let left = String::from("rust");
    let right = String::from("go");
    assert_eq!(longer(&left, &right), "rust");
}

这里返回的借用只能在两个输入借用共同有效的范围内使用，并不要求两个字符串本身同时创建、同时销毁。函数不能返回指向局部 String 的引用；如果结果由函数新建，就返回拥有数据的 String。参见生命周期。

练习：让 word_count 先接收 String，观察调用后继续使用原字符串的错误，再改回 &str。这能验证签名为何重要。

结构体、枚举与 trait ​

结构体与方法接收者 ​

结构体把有名字的字段放在一起；impl 提供方法和关联函数，其中 Self 指当前实现的类型。方法的接收者说明它如何使用实例：&self 读取，&mut self 修改，self 获取所有权。没有接收者的 new 是普通关联函数，并不是语言要求的特殊构造器。

rust
#[derive(Debug)]
struct Task {
    title: String,
    done: bool,
}

impl Task {
    fn new(title: String) -> Self {
        Self { title, done: false }
    }

    fn finish(&mut self) {
        self.done = true;
    }

    fn title(&self) -> &str {
        &self.title
    }
}

fn main() {
    let mut task = Task::new(String::from("learn Rust"));
    task.finish();
    assert!(task.done);
    assert_eq!(task.title(), "learn Rust");
    println!("{task:?}");
}

#[derive(Debug)] 为类型自动实现 Debug 这个 trait，使其支持 {:?} 调试输出；面向用户的 {} 输出由 Display 控制，不能因为派生了 Debug 就使用 {}。后文的 derive(PartialEq) 同样通过自动实现 trait 让值支持相等比较。参见方法语法。

枚举表达状态 ​

枚举可以让每个变体携带不同的数据。Option<T> 的 Some(T) / None 表达有值或无值；用 match 明确处理缺失值，不能把 None 当成任意一种默认数值。

rust
fn first_nonempty(lines: &[&str]) -> Option<usize> {
    for index in 0..lines.len() {
        if !lines[index].is_empty() {
            return Some(index);
        }
    }
    None
}

fn main() {
    match first_nonempty(&["", "rust"]) {
        Some(index) => assert_eq!(index, 1),
        None => panic!("示例应存在非空行"),
    }
    assert_eq!(first_nonempty(&[]), None);
}

0..lines.len() 不包含右端点，保证上例索引在范围内；Some(index) 携带位置，末尾 None 表示遍历后未找到。只关心一个变体时可用 if let Some(value) = ...；需要明确处理每种状态时使用 match。参见枚举与 Option。

泛型与 trait 约束 ​

泛型复用类型结构，trait 描述类型提供的行为。T: Trait 是编译器必须能验证的约束。先写具体类型版本，只有行为确实重复时再抽取泛型。

下例的 struct Note(String); 是元组结构体，拥有一个 String 字段，用 .0 访问。它实现 Summary 后，才能传给要求 T: Summary 的函数。

rust
trait Summary {
    fn summary(&self) -> &str;
}

struct Note(String);

impl Summary for Note {
    fn summary(&self) -> &str {
        &self.0
    }
}

fn print_summary<T: Summary>(value: &T) {
    println!("{}", value.summary());
}

fn main() {
    let note = Note(String::from("ownership first"));
    print_summary(&note);
}

impl Trait 也可以简写参数的 trait 约束。需要在运行时保存不同具体类型、并通过同一接口调用时，再学习 dyn Trait trait 对象及其限制。trait 对象不是所有泛型的默认替代品。参见trait及trait 对象。

练习：给 Task 实现 Summary，并用同一个 print_summary 打印 Task 和 Note。
