PHP JSON 的对象、列表与缺失字段 ​

假设一条偏好设置支持部分更新。{} 保留原昵称，{"name":null} 清空昵称，{"name":"Lin"} 替换昵称。三种请求都可能是语法正确的 JSON，解析成功后还需要判断结构和字段。

解析阶段和业务阶段 ​

默认对象模式下，json_decode 把对象解析成 stdClass，列表解析成 PHP 数组。JSON_THROW_ON_ERROR 让无效 JSON 抛出 JsonException，这样就能把合法的 JSON 字面量 null 与解析失败区分开。随后要求顶层为对象，才进入字段逻辑。此处使用 property_exists；若改用 isset，明确传入的空值会被当作没传。json_decode · property_exists

php
<?php
declare(strict_types=1);
function nicknameUpdate(string $json): string {
    $patch = json_decode($json, false, 512, JSON_THROW_ON_ERROR);
    if (!$patch instanceof stdClass) {
        throw new DomainException('object required');
    }
    if (!property_exists($patch, 'name')) return 'keep';
    if ($patch->name === null) return 'clear';
    if (!is_string($patch->name)) throw new DomainException('name must be text');
    return 'set:' . $patch->name;
}
foreach (['{}', '{"name":null}', '{"name":"Lin"}', '[]', '{"name":3}', '{'] as $input) {
    try {
        echo nicknameUpdate($input), PHP_EOL;
    } catch (JsonException $e) {
        echo 'invalid JSON', PHP_EOL;
    } catch (DomainException $e) {
        echo $e->getMessage(), PHP_EOL;
    }
}

六行输出依次是 keep、clear、set:Lin、object required、name must be text、invalid JSON。合同允许空字符串，因此 {"name":""} 应输出 set:。如果业务决定拒绝空名，只需增加字段规则，无须改变解析异常的处理。

空对象为何可能变成列表 ​

用关联数组模式解析时，空对象 {} 和空列表 [] 都可能变成同一个空 PHP 数组。再次编码时，这个空数组通常表示列表。非空数组的键也重要：顺序从零连续递增的整数键可编码成 JSON 数组，有洞的整数键则会编码成对象。array_values 会重新编号，只有协议本来就要求顺序列表时才适用。想保留对象身份时，保持对象表示直到输出；想区分字段是否出现，就在解码后保留这种信息。练习时把空对象、空列表和 [0 => 'a', 2 => 'b'] 分别编码，再写下接收端看到的结构。json_encode · 数组的键
