C POSIX 线程：创建、互斥与退出前收拢 ​

前置：C指针与对象生存期。jobs、scan和run来自双文件统计库的scan.c；先确认谁持有参数，再推演线程结束与销毁顺序。

用一个时序检查任务参数的生存期：主线程填好 jobs[0]，创建线程，工作线程读参数，主线程 pthread_join 返回，最后才可释放参数。若第二次创建失败，前一个线程也必须经过这条收尾路径。

专题入口：C POSIX 文件接口：描述符、短读写与错误契约 · C POSIX 线程：创建、互斥与退出前收拢 · C POSIX 完整实践：双文件字节统计库 · C POSIX 排错：系统错误、死锁与不完整输出

C线程参数为什么不能指向短命栈变量 ​

pthread_create 可能在调用返回之前就开始运行新线程。必须先初始化 jobs 的 path 与 owner，再创建线程；参数对象的生存期必须覆盖线程结束。项目把 jobs 放在堆上的 scan 中，run 在返回之前 join，destroy 只允许在 run 之后同一拥有者调用。

不能在循环里把同一个局部 i 的地址交给所有线程，也不能从启动函数返回时释放它们还在使用的状态。线程调度顺序不确定，不能根据屏幕上偶尔观察到的顺序推断安全。

C部分线程创建失败如何清理 ​

started 只记录成功创建的线程数。第二次创建失败时，第一次线程仍可能正在读取；run 必须对 threads[0..started) 执行 pthread_join，收拢后再返回创建错误。失败的线程ID未初始化，不能参与 join。

线程只能由本拥有者 join 一次，不能同时让另一个线程 join 或 detach。join 失败不是“线程已结束”的证据；本例把这种内部不变式破坏视为致命错误并 abort，绝不继续 free 仍可能被使用的内存。普通资源不足由创建错误返回，致命路径不是业务恢复策略。

C互斥锁应该保护哪些状态 ​

两个 worker 都可能更新 total，读取、检查溢出、加法与写回必须处于同一个 pthread_mutex_lock 临界区。只锁赋值会让两线程都读到旧值；volatile 也不能让复合更新成为原子操作。每个 worker 的局部 bytes 不共享，因此读取文件时不持锁。

本例只有一把默认非稳健互斥锁，不使用递归重入或拥有者死亡恢复。lock/unlock 不应在满足这些约束的正常路径失败；不满足时中止。若改成 robust mutex，EOWNERDEAD 表示已取得锁但数据可能不一致，需要新恢复协议，不能直接沿用这里的 require_success。

C主线程何时可以读取工作线程结果 ​

join 完成后主线程再读每个 worker 的 error，不能边运行边无锁轮询。total 的并发写由 mutex 串行化，最终读取在全部 join 后；ready 只由主线程在全部成功后设为1。即使另一个线程已成功累加，任一失败也不发布报告。

attempted 在启动前置位，使 run 是一次性状态机：created → attempted → ready 或 failed。失败不支持重试，避免重复累计；第二次调用返回 EALREADY。此句柄不允许外部并发调用，内部有锁不代表所有公开操作都线程安全。
