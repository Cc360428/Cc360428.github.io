Django任务板完整工程包含哪些文件 ​

完整工程固定依赖 Django 5.2.18，目标解释器 Python 3.12，包含配置、URL、模型、表单、视图、后台、模板、手写迁移和测试规格。数据保存在本地 SQLite；不依赖外部数据库服务。环境变量直接从进程读取，.env.example 是输入说明，不会自动加载。

成功标准是已登录用户完成新增、筛选、编辑和删除，并且不能读取或修改别人的任务。新增和编辑共享表单，但不新增可编辑 owner。源码与下方所有 include 同源，README 包含未来自行安装和启动的三平台命令；交付时示例未执行。

Django绑定表单怎样保留错误输入 ​

GET 创建未绑定表单，POST 把 request.POST 交给绑定表单。不能写 request.POST or None，因为空 POST 也必须被视为一次提交并报告缺失字段。只有 POST 且 is_valid 为真才写数据库，错误时原表单连同字段错误重新渲染，输入得以保留。

成功保存后重定向列表，避免刷新浏览器重复提交同一 POST；这叫 POST/Redirect/GET。浏览器仍可能重发请求，因此它不取代数据库唯一约束或业务幂等策略。列表默认显示全部，state=open/done 才附加布尔条件，未知 state 退回全部，不拼接原始 SQL。

Django任务表单怎样携带CSRF令牌 ​

每个修改表单包含 csrf_token，渲染时产生供浏览器提交的隐藏令牌，CsrfViewMiddleware 在不安全方法中检查令牌及相关来源条件。Cookie 保存 CSRF secret 的相关值，提交令牌用于证明请求与当前站点页面的关系；登录身份本身不能代替它。

本例使用同源普通 HTML 表单，不配置跨域放行，不关闭 CSRF 中间件。登录、新增、编辑、删除和退出均覆盖 token。GET 不做删除，因此链接预取、爬虫和浏览器缓存不会误删任务。未来前后端分离时需另外分析 Origin、Cookie 属性和凭证策略，不能把本例表单步骤直接等同跨域配置。

Django任务板需要哪些隔离测试 ​

测试客户端覆盖正常 CRUD 与完成状态筛选，也覆盖匿名跳转、越权 404、GET 删除 405、空POST、空白与超长标题、新增/编辑重复冲突、保留原标题、跨用户同名及伪造 owner。普通 TestCase 客户端默认放松 CSRF 检查，因此另建 Client(enforce_csrf_checks=True) 验证无 token 得到 403、有 token 成功创建。

测试不能只断言状态码，还要核对任务数量、owner、修改后的字段、删除结果及列表隔离。重复保存后再发 GET，确认异常恢复路径没有把后续数据库查询留在坏事务里。当前只检查测试源码和场景完整性，没有执行测试客户端，没有创建测试数据库。

tasks/models.py ​

py
from django.conf import settings
from django.db import models

class Task(models.Model):
    owner = models.ForeignKey(settings.AUTH_USER_MODEL, on_delete=models.CASCADE)
    title = models.CharField(max_length=120)
    done = models.BooleanField(default=False)
    created_at = models.DateTimeField(auto_now_add=True)

    class Meta:
        ordering = ["-created_at", "-pk"]
        constraints = [models.UniqueConstraint(fields=["owner", "title"], name="task_owner_title_unique")]

    def __str__(self):
        return self.title

class TaskForm(forms.ModelForm):

        model = Task
        fields = ["title", "done"]

    def clean_title(self):
        title = self.cleaned_data["title"].strip()
        if not title:
            raise forms.ValidationError("标题不能为空。")
        return title

tasks/views.py ​

py
from django.contrib.auth.decorators import login_required
from django.db import IntegrityError, transaction
from django.shortcuts import get_object_or_404, redirect, render
from django.views.decorators.http import require_http_methods, require_POST
from .forms import TaskForm
from .models import Task

@login_required
@require_http_methods(["GET"])
def task_list(request):
    tasks = Task.objects.filter(owner=request.user)
    state = request.GET.get("state", "all")
    if state in {"open", "done"}:
        tasks = tasks.filter(done=state == "done")
    return render(request, "tasks/list.html", {"tasks": tasks, "state": state})

@login_required
@require_http_methods(["GET", "POST"])
def task_edit(request, pk=None):
    task = get_object_or_404(Task, pk=pk, owner=request.user) if pk is not None else None
    form = TaskForm(request.POST if request.method == "POST" else None, instance=task)
    if request.method == "POST" and form.is_valid():
        saved = form.save(commit=False)
        saved.owner = request.user
        try:
            with transaction.atomic():
                saved.save()
        except IntegrityError:
            # This model has one business constraint; transaction has rolled back.
            form.add_error(None, "保存冲突，请检查是否已有同名任务，再重试。")
        else:
            return redirect("tasks:list")
    return render(request, "tasks/form.html", {"form": form, "task": task})

@login_required
@require_POST
def task_delete(request, pk):
    task = get_object_or_404(Task, pk=pk, owner=request.user)
    task.delete()
    return redirect("tasks:list")
