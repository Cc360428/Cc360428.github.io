pandas 转换机制：连接基数、分组与时区 ​

前置：类型和CSV契约。转换正确不只取决于API没有报错，还取决于行数、主键、总额和时间范围这些不变量。先验证事实表和维度表，再连接、聚合，最后排序输出。

连接基数与未匹配客户 ​

pandas合并后金额翻倍怎么查：先检查客户维度的键唯一性，再在merge指定validate='many_to_one'约束多对一关系。销售允许多个订单属于同一客户，客户表同一个ID只能有一行；重复维度会展开笛卡尔组合，即使结果形状合法也会重复计算收入。不能靠合并后drop_duplicates掩盖上游歧义。

工程用left连接保留全部销售，并设置indicator=True，检查_merge全部为both；未知客户是数据错误，不能inner连接后悄悄丢单。pandas允许空连接键互相匹配，与常见SQL NULL语义不同，因此必须先拒绝空ID。连接前后可以检查销售行数和金额守恒，但守恒不是唯一性检查的替代品。 例如某键在事实表出现 2 次、在维度表出现 3 次时，无约束连接会产生 6 行。下游再求和已经无法知道其中哪一条维度记录才是正确归属。

python
joined = sales.merge(customers, on='customer_id', how='left',
                     validate='many_to_one', indicator=True)

这是局部片段，完整前置校验在report.py。只需拼接同结构批次时用concat；join通常围绕索引，选择前先确认关联键，不要凭函数名字猜行为。官方连接指南用于核对连接验证和索引行为。

缺失与分组计数 ​

pandas分组为什么少了空地区：groupby的dropna会影响缺失键是否形成分组；本项目先将允许缺失的region填成unknown，再显式设置dropna=False。order_count使用size计算订单行数，count则统计指定列非缺失值，二者在有NA时可能不同。选择统计口径前先定义分母，不能把任一列的count都叫订单数。

as_index=False让分组键保持普通列，便于CSV输出；named aggregation为订单数和总分命名，避免多层列索引。sort=True使分组键排序，observed=True明确类别列只报告实际出现组合，减少未来默认变化影响。此处不是补齐所有月份×地区的网格，未发生交易的组合不输出；要展示零交易月份必须先定义日历维表再reindex，不能凭空推断缺行就是零。

python
summary = joined.groupby(['month', 'region'], as_index=False,
                         dropna=False, sort=True, observed=True).agg(
    order_count=('sale_id', 'size'), total_cents=('amount_cents', 'sum'))

工程金额必填，所以sum不面对“全组未知金额”问题。其他数据中默认求和可能把全缺失表现为0，应考虑min_count并显式测试。详见groupby参数。

金额精度与溢出 ​

pandas整数金额怎样避免溢出：金额采用整数分，先用Python任意精度int校验单行和全局总额，再转换int64用于分组；不能先在int64上求和再判断溢出。所有金额非负意味着任一分组总额不会超过全局总额，因而全局上界能保护每个分组。允许退款后这一证明不再成立，需要重新设计正负累计边界。

输入“1.25”不是125分，必须拒绝；负数、指数、NaN和前导零也不符合本项目格式。用float乘100再round会引入二进制表示和舍入规则，不是精确货币解析。若输入单位元，可以先用严格十进制文本解析或Decimal并定义舍入策略，然后转分。本项目刻意要求上游提供分，减少一次隐式业务变换。

行数上限10万、单笔上限10^12分使总额最多10^17，低于2^63−1；代码仍保留总额检查以便边界变化时显式失败。NumPy/pandas固定宽整数不具备Python int的自动扩展能力。 若把 10¹² 分的行上限放宽，却只在 groupby().sum() 后检查结果，固定宽度溢出可能已让分组值回绕，事后比较无法恢复原值。

UTC存储与业务月份 ​

pandas按上海月份统计怎么做：要求每个时间携带时区偏移，to_datetime先用utc=True统一瞬间，再tz_convert到Asia/Shanghai，最后strftime取当地月份。UTC的1月31日16点对应上海2月1日0点，先取UTC月份会把交易放错报表。tz_localize给无时区墙钟指定解释，tz_convert则转换已有时区瞬间，二者不能互换。

工程输入限定2025年完整秒ISO时间，解析器还负责检查真实日历；正则匹配不保证2月30日存在。当地业务窗口为[2025-01-01, 2026-01-01)，上界排除。原始文本年份2025不保证转换后的当地时间仍在2025，必须另验窗口。时区数据来自操作系统或tzdata；Windows准备环境时保留tzdata依赖。

to_datetime提供errors='raise'和UTC转换参数。本工程拒绝无偏移时间，不猜夏令时重复时刻，不把coerce产生NaT后删除行当成成功清洗。

复制和赋值边界 ​

pandas链式赋值为什么不可靠：避免frame[mask]['x']=value，使用一次loc定位并赋值，或先copy后修改独立结果。pandas 2.3.3的Copy-on-Write是可配置行为，3.0采用CoW默认语义；本组不依赖切片写入原表的副作用，函数内只修改自己创建的数据对象。deep=True也不递归复制object列里嵌套的任意Python对象。

需要修改原表时用 frame.loc[mask, 'x'] = value；需要新报表时用 selected = frame.loc[mask].copy() 并只修改selected。CoW主要改变共享底层数据时何时复制，不保证嵌套可变对象隔离，也不等于线程安全。参考CoW版本说明。

转换练习 ​

客户001出现两行地区、另有一条客户999销售：分别预测many_to_one验证和_merge检查的作用。再给输入增加2025-12-31T16:00:00Z，判断它是否属于有效窗口。最后解释为什么有两个金额NA的分组不应自动宣称收入0。

参考解法

重复001在连接验证前已被客户唯一性检查拒绝；只保留唯一001后，999仍因未匹配失败。该时间转上海为2026-01-01T00:00:00+08:00，属于排除上界。未知金额不等于没有收入，先定义数据质量规则，再决定拒绝或保留NA；不能直接套用项目的必填金额假设。
