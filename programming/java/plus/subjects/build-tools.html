Java 构建模型：从 javac 到 Maven 生命周期与 Gradle 任务 ​

javac 接收源码、编译类路径和目标版本，输出类文件；java 使用运行类路径加载入口类和依赖。源码多了以后，工程还需要协调资源复制、依赖解析、测试和打包。Maven 用生命周期阶段和绑定的插件目标描述这些步骤，Gradle 用项目任务及其依赖关系描述它们。先知道需要哪种证据，再选择命令。

从实际文件看两种类路径 ​

在 examples/java/study-report 目录执行下列命令。该项目只依赖 JDK 标准库，测试源码自己提供 main。

shell
javac --release 21 -encoding UTF-8 -d out src/StudyReport.java test/StudyReportTest.java
java -cp out StudyReportTest
java -cp out StudyReport sample.tsv

第一条同时编译应用和测试；第二条从 out 找到测试类，预期 study tests passed；第三条预期依次输出 go=30、java=30。删除测试文件名、改用一个新的空输出目录后，业务仍可能编译成功，测试入口却找不到。构建产物存在与测试已执行是两个独立的判断。--release 21 限制可使用的 Java 语言和标准 API 目标，即使编译器来自更新的 JDK，也不能据此推断目标机器已经安装所需运行时。

Maven 的阶段与依赖作用域 ​

转到 examples/java/p2-spring，pom.xml 指定 Java 21、Spring Boot 父项目及 Web、校验、JPA 等依赖。H2 的 runtime 作用域允许程序运行时找到驱动；spring-boot-starter-test 的 test 作用域为测试提供库，正常应用不该依赖其中的测试类。观察依赖时应注明在看编译、测试还是运行的类路径。

mvn test 推进默认生命周期到 test，使用项目绑定的插件运行单元测试；mvn package 继续到打包。mvn verify 再推进到校验阶段，实际是否运行额外的集成测试由 POM 的插件绑定决定。mvn install 会把本项目产物写入本地仓库，仅在其他本机项目需要解析这份产物等场景才有必要。验收时查看 Surefire 的测试数量及结果，避免仅凭 BUILD SUCCESS 把“跳过测试”误作通过。

Gradle 用任务图回答相同问题 ​

在采用 Gradle Java 插件并提交 Wrapper 的项目里，可以用 ./gradlew tasks --all 看任务，用 ./gradlew build --dry-run 看计划顺序，用 ./gradlew test --tests "包名.测试类" 选择测试。Windows PowerShell 可替换为 .\gradlew.bat。--dry-run 不执行测试动作；真实运行时还要分清已执行、命中缓存、已是最新、跳过等结果。仓库这份 Spring 示例使用 Maven，其目录没有 Gradle Wrapper。

自测：若应用运行时报某类缺失，先检查它是否只出现在测试作用域，以及打包产物和启动类路径是否包含它。若出现“没有运行测试”，先确认测试类能被项目约定的运行器发现，再检查筛选参数。对应命令按场景收在 Java 操作与命令。Maven 生命周期 · Gradle Java 插件
