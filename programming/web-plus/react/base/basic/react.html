React 首批完整实践：组件、状态快照与阅读清单 ​

React/Vite 构建、模型测试和 Chromium 交互是原文 2026-10-17 的历史记录；本轮未重跑。下文仍区分模型断言、组件事件和生产预览的检查范围。

前置为HTML表单、CSS布局、JavaScript函数/数组/模块。TypeScript可后续接入，不把另一门类型扩展或Vue设为开始React的强制条件。本批用React自身组件模型组织；已有基础参考可按知识点巩固，本篇给出从安装到构建的完整程序。

环境、版本与运行 ​

本批React/react-dom19.3.1、Vite8.3.4、@vitejs/plugin-react6.1.2，Node24.21.0/npm11.19.0；Windows amd64实际构建，Chromium实际操作。版本在2026-10-17核对npm发行信息和官方要求后固定。只在教学子目录安装，不升级本站VitePress依赖。macOS不纳入验收。

进入examples/web-plus/react，执行npm ci、npm test、npm run build，再npm run preview -- --port 5190，打开终端显示的127.0.0.1地址。首次安装需要网络与锁文件；独立复制源码无锁文件时先npm install生成锁，不要对不存在的锁执行npm ci。停止预览用Ctrl+C。本程序不接外部服务，不需要登录。

预期空清单；添加“学习React”得到1条，标记完成后完成数1；筛选未完成会隐藏它，切回全部再出现；删除后为0。刷新恢复空列表，这是本项目明确的内存状态约定；不是localStorage持久化项目。先按预期完成，再进入组件机制。

JSX、组件与单向数据流 ​

组件是返回界面描述的函数；JSX需由构建工具转换，不是浏览器直接执行的HTML。App持有数据，NoteList接收只读props，点击后回调通知父组件更新；子组件不修改传入note。key用稳定id，不能用过滤后的数组下标，否则重排/删除时可能把组件状态对应错对象。

大写组件名、闭合标签、className/htmlFor及事件函数是基本约定。插值标题会按文本转义，不使用dangerouslySetInnerHTML解析输入。提取组件的理由是职责清晰，本批只分根组件与列表组件，不预建状态库和多层架构。

state快照、受控表单与派生值 ​

useState保存当前渲染的状态快照，setter安排下一次渲染；不能在调用setter后假设当前函数中的旧变量立刻改变。纯更新可以在需要时用函数形式读取待处理状态。项目每次用户事件计算新对象和新数组，不push修改既有state。

输入value与onChange成对，select同理；表单submit中preventDefault避免导航。required只拦截空字符串，纯空白、超过80码点和超过20条仍由模型拒绝。错误留在role=status，成功后清除。筛选结果和完成数由当前notes直接计算，不额外保存一份状态并用Effect追赶同步。

nextId随添加单调增加，删除不回收id；筛选只影响显示，不改变数据。模型单测既断言结果，也断言源状态没被修改。React批处理、事件闭包和对象身份都应按这一数据流理解，不凭“组件重新执行”推断浏览器DOM一定全量重建。

Effect与框架API边界 ​

Effect适合与外部系统同步。本项目把记录条数同步到document.title，并在清理时恢复之前标题；派生数量仍在渲染中算。useEffect依赖包含读取的响应式值，开发StrictMode可能额外运行设置/清理以发现问题，不应靠“只执行一次”的假设省掉清理。

请求、订阅和定时器需要各自取消或清理策略；不能把async函数直接当成返回Promise的Effect回调。本批没有业务请求，相关深入按实际需求再开；不凭一个未实现/api地址冒充完整项目。React API与路由/服务框架的API分开，后者不是React核心内置。

src/model.mjs
javascript
export const initialState=()=>({nextId:1,notes:[]});
export function addNote(state,title){
 const text=title.trim();
 if(!text||Array.from(text).length>80)throw new Error('标题需要1到80个字符');
 if(state.notes.length>=20)throw new Error('最多20条记录');
 return {nextId:state.nextId+1,notes:[...state.notes,{id:state.nextId,title:text,done:false}]};
}
function requireNote(state,id){if(!state.notes.some(n=>n.id===id))throw new Error('记录不存在');}
export function toggleNote(state,id){
 requireNote(state,id);return {...state,notes:state.notes.map(n=>n.id===id?{...n,done:!n.done}:n)};
}
export function removeNote(state,id){requireNote(state,id);return {...state,notes:state.notes.filter(n=>n.id!==id)};}
export function visibleNotes(state,filter){return state.notes.filter(n=>filter==='done'?n.done:filter==='open'?!n.done:true);}
src/App.jsx
jsx
import {useEffect,useState} from 'react';
import {initialState,addNote,toggleNote,removeNote,visibleNotes} from './model.mjs';
import NoteList from './NoteList.jsx';

export default function App(){
 const [state,setState]=useState(initialState);
 const [title,setTitle]=useState('');
 const [filter,setFilter]=useState('all');
 const [error,setError]=useState('');
 const visible=visibleNotes(state,filter);
 const done=state.notes.filter(note=>note.done).length;
 useEffect(()=>{
  const previous=document.title;
  document.title=`阅读清单 · ${state.notes.length}条`;
  return ()=>{document.title=previous;};
 },[state.notes.length]);
 function submit(event){
  event.preventDefault();
  try {setState(addNote(state,title));setTitle('');setError('');}
  catch(problem){setError(problem.message);}
 }
 return <main>
  <h1>React 阅读清单</h1><p>组件、状态与父子通信；刷新会清空本次练习。</p>
  <form onSubmit={submit}><label htmlFor="title">阅读标题</label>
   <input id="title" value={title} onChange={event=>setTitle(event.target.value)} required maxLength={160} />
   <button type="submit">添加</button></form>
  <p role="status" aria-live="polite">{error}</p>
  <label htmlFor="filter">显示</label><select id="filter" value={filter} onChange={event=>setFilter(event.target.value)}>
   <option value="all">全部</option><option value="open">未完成</option><option value="done">已完成</option>
  </select>
  <p>共 {state.notes.length} 条，已完成 {done} 条</p>
  <NoteList notes={visible} onToggle={id=>setState(toggleNote(state,id))} onRemove={id=>setState(removeNote(state,id))} />
 </main>;
}

业务规则为标题去首尾空白后1–80个Unicode码点，最多20条；HTML maxlength=160是较宽松的UTF-16输入限制，实际以模型为准。模型创建新对象，渲染使用稳定id。原生label/button/select保留键盘语义，CSS在390px保持单列并对长标题换行。

import {test} from 'node:test';
import assert from 'node:assert/strict';
import {initialState,addNote,toggleNote,removeNote,visibleNotes} from './src/model.mjs';

test('添加、稳定ID更新、筛选和删除保持源状态',()=>{
 const original=initialState();let state=addNote(original,'学习框架');state=addNote(state,'完成实践');
 assert.equal(original.notes.length,0);state=toggleNote(state,2);
 assert.deepEqual(visibleNotes(state,'done').map(n=>n.id),[2]);
 state=removeNote(state,2);assert.deepEqual(state.notes.map(n=>n.id),[1]);
 state=addNote(state,'新记录');assert.deepEqual(state.notes.map(n=>n.id),[1,3]);
});
test('输入、上限与不存在ID失败，不应用部分修改',()=>{
 const empty=initialState();assert.throws(()=>addNote(empty,'   '));assert.throws(()=>addNote(empty,'x'.repeat(81)));
 let state=empty;for(let i=0;i<20;i++)state=addNote(state,String(i));
 assert.throws(()=>addNote(state,'extra'));assert.equal(state.notes.length,20);
 assert.throws(()=>toggleNote(state,99));assert.throws(()=>removeNote(state,99));
});

npm test预期两组通过，验证添加、完成/过滤、删除后id不复用、输入和数量边界、不存在id与源状态不变。它们不等于真实DOM测试；本批另在生产预览中实际走键盘提交、按钮、过滤、HTML样式文本、空白拒绝、刷新和390px。

npm run verify依次跑模型测试与生产构建；失败即非零，不执行后续成功步骤。vite preview预览dist，不是生产服务部署方案。更新源码后应重新build，不要只刷新旧预览。Invalid hook call先检查调用位置和React是否重复安装；列表警告先检查key；输入只读警告先看value/onChange配对，而不是隐藏console。

练习与参考解法 ​

  1. 把筛选后第一项标记/删除，确认按id更新原清单。2. 加标题关键词筛选，不增加第二份notes。3. 推测StrictMode重复初始化是否会重复增加记录。4. 把刷新后保留作为下一次需求时，应增加哪些失败处理？
提示与参考解法

操作回调传note.id，不使用显示位置；关键词和done条件在visible计算中组合，原notes不变。initialState仅创建空数据，用户操作不在初始化副作用中执行，开发额外检查不会多加一条。若加入持久化，要定义加载/JSON结构/配额错误、保存失败时界面承诺和跨标签策略，不能在每次渲染时直接setItem。本批未实现该需求，刷新为空是明确预期。
