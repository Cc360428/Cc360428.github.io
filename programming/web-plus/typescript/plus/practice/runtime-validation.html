TypeScript 运行时校验：从 unknown 构造业务值 ​

设想一个设置文件的内容是 {"attempts":0}。重试次数允许 0 到 3，零表示第一次失败就停止。文件系统交付的是文本；JSON 解析器理解文本语法；应用负责判断值是否符合重试策略。三层分别可能出错，类型注解只在编译期间存在。

从未知输入建立证据 ​

让 JSON.parse 的结果进入一个 unknown 变量，可阻止后续代码在未检查前随意读属性。typeof value === "object" 还允许 null 和数组。缩小到非空对象后，检查字段是否存在、是否为自有属性，以及字段值的类型。"attempts" in value 能帮助编译器收窄对象形状，但也会命中原型链，因此若契约只接受自有字段，还需单独检查。

字段为 number 并不保证是整数，Number.isInteger 又不能说明范围。分别判断能向调用方指出错误发生在哪一层。以下策略允许额外字段，但只把受支持的字段投影到一个新对象中，这样后续修改输入对象也不会改写配置。

typescript
export {};
type Settings = Readonly<{ attempts: number }>;

function readSettings(value: unknown): Settings {
  if (value === null || typeof value !== "object" || Array.isArray(value)
      || !("attempts" in value) || !Object.hasOwn(value, "attempts")) {
    throw new TypeError("missing attempts");
  }
  const count = value.attempts;
  if (typeof count !== "number" || !Number.isInteger(count)) {
    throw new TypeError("attempts must be an integer");
  }
  if (count < 0 || count > 3) throw new RangeError("attempts outside 0..3");
  return { attempts: count };
}

const input: unknown = JSON.parse('{"attempts":0,"comment":"local"}');
const result = readSettings(input);
if (result.attempts !== 0 || Object.hasOwn(result, "comment")) throw new Error("projection");
if (readSettings({ attempts: 3 }).attempts !== 3) throw new Error("upper bound");

as Settings 会告诉编译器采用一个类型视图。它不会运行 Number.isInteger，不会删除额外字段，也不会分配这份新对象。写了类型谓词的函数同样要对自己的实现负责，编译器不会证明每一行验证逻辑正确。

选择能定位问题的反例 ​

将第二段代码接在同一个文件末尾，用课程工程的 npm run build 编译，再运行 node dist/practice.js。不同反例分别验证不同边界。

typescript
function expectError(run: () => unknown, kind: typeof Error) {
  try {
    run();
  } catch (error) {
    if (error instanceof kind) return;
    throw error;
  }
  throw new Error("expected " + kind.name);
}
expectError(() => JSON.parse("{"), SyntaxError);
expectError(() => readSettings(null), TypeError);
expectError(() => readSettings({ attempts: "0" }), TypeError);
expectError(() => readSettings({ attempts: 1.5 }), TypeError);
expectError(() => readSettings({ attempts: 4 }), RangeError);
expectError(() => readSettings(Object.create({ attempts: 1 })), TypeError);

JSON 语法错误发生在调用 readSettings 之前；"0" 是可正常解析的 JSON 字符串，规则明确拒绝它按数字参与算术。最后一个例子来自直接传入的 JavaScript 对象，用来证明自有属性契约。一般 JSON 文本不会产生这样的继承字段。

参考核对
