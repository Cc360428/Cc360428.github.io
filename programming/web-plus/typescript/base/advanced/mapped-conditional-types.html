TypeScript 映射与条件类型：键筛选、联合分发与 never ​

一个报表接口有数字列、文本列和可缺失的数字列。汇总函数只能接受一定为数字的列名。把合格的键手抄成一个联合也能工作，但以后接口变化可能漏改。可以让编译器逐键检查字段类型，再把保留下来的键合并成联合。

从键映射到值联合 ​

[K in keyof T] 遍历键，T[K] 读取该键的值类型；保留的项写为 K，排除的项写为 never。最后用 [keyof T] 从这个中间对象读取全部属性值。never 没有成员，在联合中自然消去。-? 去掉中间对象的可选标记，避免索引该对象时多出一个 undefined。它不会把输入属性的值自动改成必有值。

typescript
export {};
type RequiredNumberKey<T> = {
  [K in keyof T]-?: T[K] extends number ? K : never;
}[keyof T];

type Row = { total: number; label: string; estimate?: number };
const key: RequiredNumberKey<Row> = "total";
// @ts-expect-error estimate 的读取结果还可能是 undefined
const absent: RequiredNumberKey<Row> = "estimate";

手工展开 Row 的中间结果，可以得到 {total: "total"; label: never; estimate: never}。在 strictNullChecks 下，Row["estimate"] 包含 undefined，整个值类型不能赋给 number。若业务允许缺失项参与汇总，必须另行规定如何处理空值，再调整这个筛选条件。

逐项判断还是整体判断 ​

条件类型左侧直接使用类型参数 T 时，给它传入联合，编译器会为每个成员单独判断并合并结果。把它改为 [T] extends [...] 后，检查的是整个元组能否赋给目标，联合不再逐项分发。

typescript
export {};
type Payload<T> = T extends { data: infer V } ? V : never;
type AllHaveData<T> = [T] extends [{ data: unknown }] ? true : false;
type Message = { kind: "text"; data: string } | { kind: "end" };
const text: Payload<Message> = "hello";
const every: AllHaveData<Message> = false;
// @ts-expect-error 只有 text 分支提供 data，值类型为 string
const bad: Payload<Message> = 0;

在 Payload<Message> 中，有 data 的分支推断出 string，没有的分支产生 never，最终保留 string。AllHaveData<Message> 要求两个成员都满足条件，因此得到 false。如果 T 本身是 never，分发时没有任何成员，Payload<never> 仍是 never。用 [T] extends [never] 才能专门检查整体是否为 never。

用正例和预期诊断维护契约 ​

分别把两段保存到课程工程的 src/practice.ts 后运行 npm run build。@ts-expect-error 要求下一行确实触发诊断；若修改后它意外通过，编译器会报告多余指令。要看到原始不兼容错误，去掉指令并再次构建。负例应尽量保持单一错误，避免别处的拼写错误意外满足预期。

练习把 estimate 改为必需的 number。此时它应当进入合法键，原来的预期诊断就会失效。再为 Message 加上带 data: number 的分支，观察 Payload<Message> 如何变为 string | number。这些类型变换在输出 JavaScript 中会被擦除，接收真实消息时仍要校验判别字段和值。TypeScript 条件类型 · TypeScript 映射类型
