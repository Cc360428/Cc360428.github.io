TypeScript 首批课程：收窄、unknown边界与完整统计库 ​

TypeScript 类型检查、TS2322 负例和编译后 JavaScript 的运行记录属于原文 2026-10-17 批次；本轮未重跑，需分别核对编译诊断与运行结果。

前置是JavaScript值与函数、数组和对象、ES模块。TypeScript给JavaScript增加静态检查；编译器接受一个程序不代表外部JSON符合业务约定，也不会替运行时分配另一套“类型对象”。本路径不要求先学React或Vue。

版本、工程与首次运行 ​

核对2026-10-17，项目固定TypeScript7.0.2，实际Node24.21.0/npm11.19.0，Windows amd64运行。编译器从项目依赖调用，不依赖全局tsc，避免编辑器与终端版本不同；package-lock记录依赖。TypeScript7当前稳定状态以官方主页与npm发行元数据核对，不把旧版本迁移结论当全部项目已兼容。

仓库examples/web-plus/typescript目录执行npm ci、npm test、npm run demo。首次需要可达npm注册表，之后以缓存是否齐全为准；不承诺没缓存也能离线安装。独立按源码重建且没有锁文件时先npm install生成锁，再使用npm ci；不要删仓库锁文件“修复”安装错误。macOS不纳入本轮验收。

编译输出到dist，源码在src；demo预期{"total":2,"done":1,"open":1}。npm run build运行tsc，不运行测试；npm test先编译再执行Node测试，不能拿“有dist文件”代替本轮构建通过。

类型、联合与收窄 ​

类型注解描述允许的值；赋值要兼容，分支中的typeof、判空或判别字段可缩小范围。string | undefined要求先处理缺值，!非空断言只压过检查，不生成运行判断。类型别名和interface都可描述对象形状，不需要为每个简单数据都定义class。

保存为项目src/concepts.ts；执行npm run build后node dist/concepts.js，预期无输出、退出0：

typescript
type Result<T> = {ok: true; value: T} | {ok: false; error: string};
function first<T>(values: readonly T[]): T | undefined { return values[0]; }
function label(result: Result<number>): string {
    return result.ok ? String(result.value) : result.error;
}
const value = first([1, 2]);
if (value !== 1 || first([]) !== undefined || label({ok: false, error: "empty"}) !== "empty") {
    throw new Error("concept check failed");
}
export {};

泛型保留输入与输出之间的类型关系，不等于any；上例first可能没结果，所以显式返回undefined。readonly表达通过当前类型视图不能修改，不冻结运行时对象。strict及noUncheckedIndexedAccess帮助暴露空值和越界假设，仍须在运行时处理真实输入。

unknown、断言与运行边界 ​

JSON.parse解析语法，其结果不能凭一条as Note[]获得实际校验。接收unknown后先验证数组、长度、字段类型与业务约束，再构造Note值；把unknown改成any只是放弃检查。类型断言在运行时被擦除，非法JSON字符串还会在解析阶段先失败。

本项目Note为readonly的id/title/done对象；解析会创建新对象、修剪标题并检查ID唯一性。Number.isSafeInteger既排除小数也约束安全整数；done必须为boolean，字符串"false"不能按真值当完成。输入数组最多20项，标题1–80个Unicode码点，id正安全整数。TypeScript结构类型不意味着运行中所有额外字段都被拒绝；本项目只取需要字段，不把它称为严格通用schema引擎。

模块、配置与编译产物 ​

项目package.json为type:module，tsconfig选择NodeNext模块规则，TS中相对import若出现则应按实际输出扩展名约定。target ES2022描述输出语法，lib ES2022描述可用的标准声明，不自动添加polyfill，也不赋予浏览器Node文件权限。types:[]防止意外吸收上层测试工具的全局类型。

rootDir明确src，outDir为dist，noEmitOnError在编译失败时阻止本次输出；它不自动清理以前成功生成的dist。因此失败后不能继续执行旧文件冒充新版本结果。Vite的源码转换与tsc完整类型检查是不同职责；框架工程是否类型检查应检查具体scripts，不依赖文件后缀猜测。

src/report.ts
typescript
export type Note = Readonly<{id: number; title: string; done: boolean}>;
export type Summary = {total: number; done: number; open: number};

export function parseNotes(value: unknown): readonly Note[] {
    if (!Array.isArray(value) || value.length > 20) throw new Error('expected at most 20 notes');
    const seen = new Set<number>();
    return value.map((item: unknown): Note => {
        if (typeof item !== 'object' || item === null) throw new Error('invalid note');
        const row = item as Record<string, unknown>;
        if (typeof row.id !== 'number' || !Number.isSafeInteger(row.id) || row.id < 1 || seen.has(row.id)
            || typeof row.title !== 'string' || !row.title.trim() || Array.from(row.title.trim()).length > 80
            || typeof row.done !== 'boolean') throw new Error('invalid note fields');
        seen.add(row.id);
        return {id: row.id, title: row.title.trim(), done: row.done};
    });
}

export function summarize(notes: readonly Note[]): Summary {
    const done = notes.filter(note => note.done).length;
    return {total: notes.length, done, open: notes.length - done};
}

import {test} from 'node:test';
import assert from 'node:assert/strict';
import {parseNotes,summarize} from './dist/report.js';

test('unknown数据先校验再统计，不修改输入',()=>{
 const rows=[{id:1,title:'  学习类型  ',done:true},{id:2,title:'运行测试',done:false}];
 const notes=parseNotes(rows);
 assert.equal(notes[0].title,'学习类型');assert.equal(rows[0].title,'  学习类型  ');

});

report.test.mjs包含两组测试，覆盖有效与空数组、不修改输入、非法字段、重复ID、假布尔值和空标题；当前目录还包含深入课程的advanced.test.mjs，因此npm test预期共四组通过。npm run demo输出总数2、完成1、未完成1；改变done字段时先预测，再运行核对。统计函数的静态参数类型描述内部调用契约，外部数据必须先经过parseNotes。

TS2322反例与诊断 ​

故意错误文件放fixtures，不加入正常include范围：

fixtures/invalid.ts（预期编译失败）
typescript
const count: number = "three";
export {count};

在项目目录运行npx --no-install tsc --strict --noEmit --ignoreConfig fixtures/invalid.ts，预期非零退出并出现TS2322：string不能赋给number。ignoreConfig用于这次独立文件检查，项目构建仍用tsconfig；不要把负例加进正式src再宣称正常构建失败是工具问题。负例不运行JavaScript，也不执行未定义行为。

TS18048等“可能未定义”先检查接口和判空；Cannot find module先核对包/路径/扩展名和模块解析；浏览器“找不到process”不是通过装一个类型包就能获得Node运行时。skipLibCheck不会验证业务输入；压过错误也不等于完成修复。

练习与参考解法 ​

  1. 添加两条相同id，解释编译为何未必报错而运行要失败。2. 为只读数据加按完成状态选择函数，不修改原数组。3. 给Result增加第三种状态，怎样让遗漏分支在编译期暴露？4. 比较tsc成功、测试成功和demo成功分别证明什么。
提示与参考解法

ID唯一属于值之间的业务约束，不是本例Note形状能表达的属性；parseNotes的Set负责拒绝。筛选可接收readonly Note[]并返回filter生成的新数组，分别测空/全完成/全未完成。判别联合配合switch和never穷尽检查，在增加分支时产生未覆盖诊断。编译只检查静态约束，测试只验证所覆盖行为，demo只证明给定输入实际执行成功；三者不能互相替代。
