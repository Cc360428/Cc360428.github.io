TypeScript 类型推断与收窄：从值到可用操作 ​

一段 JavaScript 接受订单号，数字 0 和空字符串都可能是有效输入，缺省值则是 undefined。TypeScript 可以在运行前检查每个分支可做哪些操作。检查依据包括声明、初始值和到达当前语句所经过的条件。传进程序的真实值仍由 JavaScript 执行时决定。

从初始值推断类型 ​

let phase = "idle" 的变量可以更新，编译器通常将它推断为 string。const phase = "idle" 不能重新绑定，可以保留字面量类型 "idle"。一个 const 对象里的可写属性仍可能变化，因此 {phase: "idle"} 的 phase 通常推断为 string。显式标注联合能约束将来的赋值。对于固定表，也可以用 as const 保留字面量并取得只读的类型视图。

类型还能从使用位置向内传递。把一个回调传给 ["a", "b"].map(...) 时，数组元素的类型为回调形参提供上下文。函数参数若既无注解又无上下文，在 strict 模式下会收到隐式 any 诊断。

初次操作可在仓库的 examples/web-plus/typescript 目录运行 npm ci，把下面的代码保存为该项目的 src/practice.ts，然后运行 npm run build 和 node dist/practice.js。该项目固定编译器版本并启用 strict。后续独立例子可替换同一练习文件。

typescript
export {};
type Phase = "idle" | "ready";
let phase: Phase = "idle";
phase = "ready";
const names = ["Ada", "Lin"].map(name => name.toUpperCase());
if (phase !== "ready" || names.join(",") !== "ADA,LIN") throw new Error("inference");

// @ts-expect-error 这个标签不在 Phase 联合内
const invalidPhase: Phase = "done";

分支中的类型如何变化 ​

对 string | number | undefined，直接调用 toUpperCase 没有足够依据。typeof input === "string" 能证明当前分支是字符串；检查 input === undefined 后提前返回，则后续语句只面对剩余类型。不能用 if (!input) 代替这一次判空，否则合法的零和空串都被归入缺省分支。

typescript
export {};
function display(input: string | number | undefined): string {
  if (input === undefined) return "(absent)";
  if (typeof input === "number") return input.toFixed(0);
  return input.toUpperCase();
}
if (display(0) !== "0" || display("") !== "" || display("a") !== "A"
    || display(undefined) !== "(absent)") throw new Error("unexpected display");

检查中的 number 包括 NaN 等 JavaScript 数值。如果订单号只允许非负安全整数，还要在输入边界检查 Number.isSafeInteger 和范围。as number 不会做这项工作。

参考核对

只排除 undefined 和 number 后，结尾分支仍包含 null，不能无条件调用 toUpperCase()。在首行显式比较两种空值，或使用 input == null 处理这两种空值。再用原来的四种输入及新增的 null 验证各自的输出。TypeScript 控制流收窄
