Go 函数与闭包：传值、返回值与捕获 ​

前置是变量作用域与切片的值和底层数组。读一个调用时，先问哪些值在调用时复制，再问这些值是否还指向调用方持有的对象。

函数签名与值传递 ​

func add(a, b int) int 接受两个整数并返回一个整数。参数是被调用函数自己的变量，进入函数时由实参初始化。给参数 a 再赋值，调用方原来的整数仍保持原值。传指针也遵循相同规则，两边各有一份指针值，可以沿着它访问同一个对象。

切片参数揭示了这个区别。若函数执行 s[0] = 9，调用方看到同一底层数组的改动。若执行 s = append(s, 9)，新长度只保存在本地切片值，需要返回给调用方。func sum(xs ...int) int 在函数体中用切片接收可变数量的实参，已有切片可用 sum(values...) 传入。

多返回值常把结果与错误分开，例如 (int, error)。每个返回值也有类型。命名返回值在进入函数时具有该类型的零值，较长函数写出明确的返回表达式有助于核对每条路径。递归调用需要可到达的终止条件，否则小输入的正确结果也无法保证大输入能结束。

闭包保存的是变量 ​

函数可以赋给变量、传给别的函数，或者从函数中返回。函数体若引用外层作用域的变量，两者共同组成闭包。每次调用下面的 counter 都创建一份新的 n。返回后的多次调用持续修改它，所以能记住上次的结果。把返回的函数再赋给另一变量只是多了一个入口。

go
package main

import "fmt"

func counter() func() int {
	n := 0
	return func() int {
		n++
		return n
	}
}

func main() {
	first := counter()
	alias := first
	second := counter()
	fmt.Println(first(), alias(), second())
}

预期输出

text
1 2 1

前两次调用共享同一个 n，第三次读写另一份 n。计数状态的存活由是否还能被使用决定，调用 counter 的栈帧返回后仍然能访问。若两个 goroutine 同时执行 first，两次读改写共享同一变量，仍须遵守同步协议。

循环变量与语言版本 ​

闭包保存变量的规则会影响延迟执行的回调。采用 Go 1.22 及以后语言版本时，for i := 0; i < 3; i++ 在不同迭代中有各自的 i，for _, value := range xs 的迭代变量也是如此。将三个回调保存起来，在循环结束后顺序调用，三轮读取各自的绑定，可得到 0、1、2。

若先在循环外声明 var i int，循环头用 i = 0，整个循环重用同一变量。回调在循环完成后才读取它，因而都读到 3。查看旧项目时要读 go.mod 的 go 语言版本，安装了新工具链仍可能按较旧的语言语义编译。

练习与自检 ​

把 alias := first 改为 alias := counter()。若要把某一轮的值固定下来，同时兼容较老语言版本，应把值传到哪个作用域？

参考解法

修改后是 1 1 1。在循环体中定义一个新的局部变量接收当轮值，再让回调引用该局部变量；也可以把值作为参数传给创建回调的函数。每一次调用分别初始化自己的参数。
