Go 结构体、方法与接口 ​

前置是函数的值传递。把任务标为完成时，有三个问题需要分别回答：改的是哪个对象，哪个类型能调用方法，以及哪个类型可以传给要求这种行为的函数。

结构体、指针和命名类型 ​

type Task struct { Title string; Done bool } 定义了一个新类型。Task{Title: "学习"} 的 Done 字段取零值 false。copy := task 将字段逐个复制，布尔字段各自独立，切片等字段仍可能共享底层对象。包含已使用的锁时应避免复制整个结构体。

p := &task 取出地址，p.Done = true 沿着指针写到原任务。普通指针的零值是 nil，解引用之前需保证有目标。new(Task) 返回指向零值任务的指针，其存储位置由编译器判断。嵌入字段可提升方法，多个同名成员有歧义时应写出完整选择路径。

type TaskID int64 创建一个不同于 int64 的定义类型，可在本包为它定义方法。type ExternalID = int64 创建别名，两种写法表示同一类型。定义类型让用户 ID 与任务 ID 各自进入不同的函数签名，涉及不同类型的赋值通常需要显式转换。

接收者与修改范围 ​

方法将接收者作为一次调用的输入。值接收者 func (t Task) Finish() 得到任务副本，在里面改变 t.Done 只影响该副本。改为 func (t *Task) Finish() 后，两个指针值仍指向同一个任务，调用者能看到状态变化。值接收者如果含有 map 或切片，沿引用修改底层数据依然可见。

接口匹配看方法集 ​

Task 的方法集包含接收者为 Task 的方法；*Task 的方法集同时包含 Task 与 *Task 的方法。接口按方法名和完整签名匹配，无需显式声明实现。使用方要求 Finish()，就可以接收任何拥有这个方法的具体类型。

go
package main

import "fmt"

type Task struct{ Done bool }

func (t *Task) Finish() { t.Done = true }

type Finisher interface{ Finish() }

func complete(f Finisher) { f.Finish() }

func main() {
	task := Task{}
	copied := task
	complete(&task)
	fmt.Println(task.Done, copied.Done)
}

预期输出

text
true false

直接对可寻址的局部变量写 task.Finish() 时，语言允许按 (&task).Finish() 调用。把 task 赋给接口时，检查的仍是 Task 本身的方法集，所以 complete(task) 无法编译。把接收者改为值会满足接口，却会把 Done 写进副本。具体对象是否真的改变，须结合接收者和实现一起判断。

接口中的 nil 与类型断言 ​

接口值携带动态类型及该类型的值。零值接口没有动态类型。var p *Task; var f Finisher = p 将 nil 指针装入接口后，f == nil 为假，它有动态类型 *Task。若调用上面的 f.Finish()，方法在访问 t.Done 时就会解引用 nil。返回 error 也有同样的问题，成功分支应直接返回 nil。

v, ok := f.(*Task) 能安全地查询动态类型。这里即使 p 为 nil，仍会得到 ok == true 和一个 nil 的 v，因为断言判断的是类型。接口适合把一组不同实现交给同一段业务逻辑，具体输入类型已知、算法需保留元素类型时可看泛型与约束。

练习与自检 ​

在上例中改成 complete(&copied)，预测输出。给 Finish 换成值接收者后再预测一次。

参考解法

修改指针目标后输出 false true。换成值接收者后，方法里的字段属于临时副本，输出变为 false false。
