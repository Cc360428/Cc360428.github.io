Go 包与模块：导入、导出与依赖方向 ​

前置是第一个可执行程序和函数签名。当一个小程序既要从终端使用，又要让测试直接调用里面的计算，可以把计算提取到独立的包。

包、模块与工作目录 ​

包由同一目录中参与当前构建的一组源文件组成。包内普通源文件声明相同的包名，目录还可包含使用外部测试包名的 _test.go。包名决定代码中怎样引用它；导入路径在模块内通常由 go.mod 中的模块路径加目录的相对路径构成。两台电脑把项目摆在不同目录，同一个导入路径仍应有效。

模块是统一记录依赖与语言版本的单位，能够包含多个包。在空目录执行 go mod init example.com/study，创建 mathutil 子目录，再保存下列两个文件。它们属于同一个模块，各自只有一个包声明。

mathutil/add.go

go
package mathutil

func Add(a, b int) int { return a + b }

main.go

go
package main

import (
	"fmt"
	"example.com/study/mathutil"
)

func main() { fmt.Println(mathutil.Add(1, 2)) }

在模块根目录执行 go run .，预期输出

text
3

Add 的首字符是 Unicode 大写字母，可被其他包引用。把它改成 add 之后，工具仍能找到包，但 main 无法访问该成员。若把导入路径写错，失败发生在解析包时，这两类问题应分开检查。

go.mod 保存模块身份、语言版本和所需依赖等约束。go.sum 保存下载过的相关模块内容和模块声明的校验摘要。示例只用标准库和同模块包，可能根本没有 go.sum。go mod tidy 会按导入关系增加缺失项、移除不再需要的项，文件已符合要求时也可能没有差异。外部模块如何选版本，见模块依赖工作流。

包之间的依赖方向 ​

每条 import 都让编译器在处理当前包前先处理被导入包。相互导入会形成循环，工具无法按依赖顺序构建它们。本例依赖关系是 main → mathutil。若计算函数为了打印结果又导入入口包，就把原本独立的计算绑到了一个特定程序。让计算返回值，由入口打印，可同时支持终端与测试。

当函数需要文件、存储等依赖时，可以通过普通参数或构造函数传入。构造函数在返回可用对象前验证必需依赖，资源的创建者与使用者约定关闭责任。对下游包只要求一个行为时，把小接口定义在调用方可以降低它对具体实现的依赖。导入路径能告诉你谁在编译期依赖谁，构造函数参数则说明运行时由谁提供对象。通过 io.Writer 约定依赖与资源所有权

练习与自检 ​

将 mathutil 目录改名为 arith，保留 package mathutil。需要更新调用处的哪一部分？然后把可导出符号 Add 改为 add，再判断失败发生在哪一步。

参考解法

导入路径改为 "example.com/study/arith"，通过该路径找到的包仍声明为 mathutil，调用依旧写 mathutil.Add。函数名改为小写后即使找对目录，包外仍不能访问它。实际项目常让包名和目录末段一致，便于从调用追到源文件。
