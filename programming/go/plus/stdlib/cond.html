Go 条件变量：同一把锁、条件循环与关闭 ​

前置：锁与共享不变量和并发取消。条件变量适用于多个任务围绕一个受锁保护的条件协同工作。队列的事实保存在 tasks 和 closed 中；通知只让等待者有机会重新检查这两个字段。

Wait 等待的是条件 ​

消费者持锁检查“可取到任务，或者队列已关闭”。条件不成立时，Wait 原子地解锁并进入等待，其他生产者可以获得锁。Wait 返回前会重新加锁。若把检查和进入等待拆成两个独立步骤，生产者可能刚好在这段缝隙中通知，消费者随后才睡下。Go 的 Wait 只在 Signal/Broadcast 唤醒后才返回；仍要用 for 检查谓词，因为收到通知与重新获得锁之间可以发生新的状态变化。sync.Cond

队列状态Get 的决定Put 的决定
开、空持锁检查后 Wait加入任务并 Signal
开、非空取出队首任务加入任务并 Signal
关、非空继续排空已有任务拒绝新任务
关、空返回结束拒绝新任务

两个消费者的唤醒顺序 ​

A 在空队列中等待。生产者加入任务 7，Signal 唤醒 A，然后释放锁。B 此时也调用 Get，并先取得锁，拿走 7。A 之后虽然从 Wait 返回，眼前的队列又空了。若用 if 跳过复查，A 会访问空切片；for 则让它再次等待。Signal 只让某个等待者可运行，不保留未来的任务，也不授予它下一次拿锁的优先权。

关闭时应持锁把 closed 设为 true，再 Broadcast。关闭一旦发生，将来可能再没有 Put 唤醒其他消费者；只 Signal 一人会让其余等待者永远睡着。晚到的消费者直接读 closed，能观察到停止状态，无需补发历史通知。

可关闭队列 ​

Get 的最小临界区如下。构造器应让 sync.NewCond(&q.mu) 与访问 tasks、closed 使用同一把锁。生产者成功入队后 Signal，Close 更新状态后 Broadcast。完整可测试实现包含在标准库练习模块。

go
q.mu.Lock()
defer q.mu.Unlock()
for len(q.tasks) == 0 && !q.closed {
    q.ready.Wait()
}
if len(q.tasks) == 0 {
    return 0, false
}
value := q.tasks[0]
q.tasks = q.tasks[1:]
return value, true
完整队列
go
// Package condqueue implements a closable FIFO queue for integers.
package condqueue

import "sync"

type Queue struct {
	mu     sync.Mutex
	ready  *sync.Cond
	tasks  []int
	closed bool
}

// New returns an empty, open queue.
func New() *Queue {
	q := &Queue{}
	q.ready = sync.NewCond(&q.mu)
	return q
}

// Put adds value unless the queue is closed.
func (q *Queue) Put(value int) bool {
	q.mu.Lock()
	defer q.mu.Unlock()
	if q.closed {
		return false
	}
	q.tasks = append(q.tasks, value)
	q.ready.Signal()
	return true
}

// Get waits for work and returns false once the closed queue is empty.
func (q *Queue) Get() (int, bool) {
	q.mu.Lock()
	defer q.mu.Unlock()
	for len(q.tasks) == 0 && !q.closed {
		q.ready.Wait()
	}
	if len(q.tasks) == 0 {
		return 0, false
	}
	value := q.tasks[0]
	q.tasks = q.tasks[1:]
	return value, true
}

// Close rejects new work and lets waiting consumers drain existing work.
func (q *Queue) Close() {
	q.mu.Lock()
	defer q.mu.Unlock()
	q.closed = true
	q.ready.Broadcast()
}

锁、容量与退出 ​

每次更改谓词相关字段，都要和观察者遵守同一锁约定；构造时另造一把 Mutex 再让 Get 锁 q.mu 会破坏 Wait 的解锁协议。示例的队列无界；如果需要容量上限，还要定义“未满”谓词、何时让生产者重新检查，以及关闭时如何唤醒等待空间的人。Cond 本身没有 context 参数。只需一次性完成通知时，关闭 channel 能直接唤醒等待者，也方便放入 select。

练习与验收 ​

从仓库 examples/go/foundations 运行 go test -count=1 ./condqueue。测试分别覆盖空队列关闭、关闭后拒绝 Put、已有任务排空，以及多个消费者最终退出。并发测试用 testing/synctest.Wait 等到消费者已阻塞，再执行关闭，无需猜测 Sleep 时间。多消费者断言检查取得值的多重集合；取得队首与打印结果之间还可以被调度，输出顺序不宜作为断言。

队列测试
go
package condqueue

import (
	"slices"
	"testing"
	"testing/synctest"
)

func TestCloseDrainsAndRejectsNewWork(t *testing.T) {
	q := New()
	if !q.Put(7) || !q.Put(8) {
		t.Fatal("open queue rejected work")
	}
	q.Close()
	if q.Put(9) {
		t.Fatal("closed queue accepted work")
	}
	for _, want := range []int{7, 8} {
		if got, ok := q.Get(); !ok || got != want {
			t.Fatalf("Get() = (%d, %v), want (%d, true)", got, ok, want)
		}
	}
	if _, ok := q.Get(); ok {
		t.Fatal("closed, empty queue produced work")
	}
}

func TestWaitingConsumersExit(t *testing.T) {
	for _, work := range [][]int{nil, {1, 2, 3}} {
		synctest.Test(t, func(t *testing.T) {
			q := New()
			values := make(chan int, len(work))
			exited := make(chan struct{}, 3)
			for i := 0; i < cap(exited); i++ {
				go func() {
					for {
						value, ok := q.Get()
						if !ok {
							exited <- struct{}{}
							return
						}
						values <- value
					}
				}()
			}
			synctest.Wait() // All three consumers are blocked in Get.
			for _, value := range work {
				q.Put(value)
			}
			q.Close()
			synctest.Wait()
			if len(exited) != cap(exited) {
				t.Fatalf("only %d consumers exited", len(exited))
			}
			close(values)
			var got []int
			for value := range values {
				got = append(got, value)
			}
			slices.Sort(got)
			if !slices.Equal(got, work) {
				t.Fatalf("got %v, want %v", got, work)
			}
		})
	}
}
