Go 文件与 I/O：短读、字节流和资源所有权 ​

前置：包、错误与第一条测试。读取小型文件时可以一次取回全部内容。读取网络连接或大文件时，调用者通常只能逐段获得字节。选择接口时，先确定谁拥有原始数据、谁负责关闭资源、谁能决定输入有多大。

文件不存在与读写失败 ​

os.ReadFile 将整个文件读入内存。文件路径以进程的工作目录为起点。filepath.Join 负责拼路径，但不会寻找源代码所在目录。任务工具初次启动可以把“文件不存在”解释为空列表；若读到一半失败、没有权限或 JSON 损坏，沿用空列表写回就可能覆盖用户数据。用 errors.Is(err, os.ErrNotExist) 识别允许初始化的错误，其余错误携带文件路径返回。具体排查见读取文件失败。

对一个需要完整解析的文件，先读入或解析到临时值，再提交结果。写回时先完成编码，然后在目标目录创建临时文件，检查 Write、Close 和 Rename。这样可以把编码与临时写入失败隔离在旧文件之外。Rename 的替换原子性取决于平台和文件系统，断电后的持久性还涉及文件与目录同步。两个进程先读后写同一个文件仍会丢更新，需要单独的并发协议。

一次 Read 的两个返回值 ​

Read(p) 只承诺最多填充 len(p) 个字节。p[:n] 属于本次读取，err 描述随后如何继续。短读可以返回 n < len(p), nil；最后一批有效数据可以和 io.EOF 同时返回，也可以到下一次调用才见到 EOF。若先检查错误就退出，前一种实现会丢掉尾部。复用缓冲区时，如果把数据交给稍后执行的消费者，需要复制对应切片，或明确转交缓冲区的所有权。

下面的 Reader 在交出最后一批字节的同一次调用报告 EOF。把缓冲区大小从 2 改成 3，输出的文本仍应完整。

go
package main

import (
    "fmt"
    "io"
)

type chunks struct{ data string }

func (r *chunks) Read(p []byte) (int, error) {
    n := copy(p, r.data)
    r.data = r.data[n:]
    if r.data == "" { return n, io.EOF }
    return n, nil
}

func main() {
    r := &chunks{data: "abc"}
    var buf [2]byte
    for {
        n, err := r.Read(buf[:])
        fmt.Print(string(buf[:n]))
        if err == io.EOF { break }
        if err != nil { panic(err) }
    }
    fmt.Println()
}
text
abc

io.Copy(dst, src) 负责复制直到源结束或遇到错误，返回实际写入的字节数。源实现 io.WriterTo 时优先调用 src.WriteTo(dst)；否则，目标实现 io.ReaderFrom 时使用 dst.ReadFrom(src)；都没有才进入普通读写循环。strings.NewReader("学习 Go") 实现了 WriterTo，复制到 strings.Builder 写入 9 个 UTF-8 字节。这个结果能检查复制是否完整，不能证明普通读循环执行了几次。io.Copy 不负责关闭两端；打开文件的一方应安排释放，并检查写入方最后的关闭错误。io.Copy

从文本得到业务值 ​

strings.TrimSpace 处理两端空白，strconv.Atoi 解析本机 int 范围内的十进制整数，解析成功后才能判断业务约束。例如 " -2 " 可解析，但不能作为正数任务 ID。规定 64 位宽度的协议可使用 strconv.ParseInt(raw, 10, 64)，避免接收范围随目标架构改变。
