Go 标准库：文件、JSON 与时间 ​

前置：包与测试。本页解释文件与序列化 API；完整任务工具在开发实践。Go 1.27.2；Windows/Linux 测试通过为历史记录，本轮未执行示例；macOS 仅作平台说明，本项目不执行平台运行验证。它是单用户、单进程写入的练习，不支持多个终端同时修改同一文件。

文件不存在与 io 接口 ​

os.ReadFile 一次读入整个文件，适合这里的小型 JSON；大文件应使用 io.Reader 和流式处理。Reader 的 Read 返回实际读取字节数与错误，可能先返回有效数据再报告结束；不要只看错误丢掉有效字节。Writer 的 Write 也可能失败，不能把调用过 Write 当作保存成功。

文件路径相对于运行目录，不是源文件所在目录。用 filepath.Join 拼本机路径，不手动猜斜杠。os.ErrNotExist 表示不存在，但权限不足、磁盘故障不是“新用户没有文件”：用 errors.Is(err, os.ErrNotExist) 区分，只有该分支允许从空列表开始。

写文件先编码，再写同目录临时文件，检查 Write/Close 后 Rename 替换旧文件。失败时保留原数据；此方法不等于数据库事务，也不承诺断电持久性或所有文件系统上的原子替换。父目录必须存在。不要遇到权限错误就先删旧文件。

io.Reader 与流式复制 ​

Reader 表示“可读取字节”，Writer 表示“可写入字节”。依赖这两个接口，内存字符串和文件就能使用同一个复制函数。

go
package main

import (
    "fmt"
    "io"
    "strings"
)

func main() {
    source := strings.NewReader("学习 Go")
    var destination strings.Builder
    n, err := io.Copy(&destination, source)
    if err != nil { panic(err) }
    fmt.Println(n)
    fmt.Println(destination.String())
}

预期输出：

text
9
学习 Go

n 是字节数，不是中文字数。io.Copy 反复读写直到结束，仍需检查错误；实际文件可能在中途失败。手写 Read 循环时先处理 n > 0 的数据，再处理 err，避免丢掉最后一批数据。io.Copy 不替调用方关闭文件；谁打开资源，谁安排释放。

练习：将源字符串改为空串，预期字节数为 0，不能把空文件当读取失败。需要限制网络输入时明确设置上限，不要假定输入总很小。

strings 清理与 strconv 转换 ​

命令行参数是字符串，计算前需解析。TrimSpace 只清理两端空白；Atoi 失败时应处理错误，不能把返回的 0 当作用户输入。

go
package main

import (
    "fmt"
    "strconv"
    "strings"
)

func main() {
    value, err := strconv.Atoi(strings.TrimSpace(" 12 "))
    if err != nil { panic(err) }
    fmt.Println(value + 1)
    _, err = strconv.Atoi("12x")
    fmt.Println(err != nil)
    fmt.Println(strings.Join(strings.Split("go,sql", ","), " / "))
}

预期输出：

text
13
true
go / sql

Atoi 使用本机 int 范围；协议要求固定 64 位时用 strconv.ParseInt(raw, 10, 64)。解析成功不等于业务有效：ID 还必须为正数，页大小还应受上限约束。

练习：改为 " -2 "。解析成功后在业务层拒绝负数，解析器只检查数字语法和范围。

JSON 字段不导出与时间格式 ​

JSON 编码只处理可导出的结构体字段：名字必须大写；标签 json:"title" 决定对外键名，不会让小写私有字段自动导出。解码到结构体要传地址，因为解码器要修改变量。格式错误应返回错误，不要吞掉后用零值覆盖旧文件。

go
package main

import (
    "encoding/json"
    "fmt"
    "time"
)

type Record struct {
    Title string `json:"title"`
    hidden string
}

func main() {
    data, err := json.Marshal(Record{Title: "学习 JSON", hidden: "不会导出"})
    if err != nil { panic(err) }
    fmt.Println(string(data))
    var loaded Record
    if err := json.Unmarshal(data, &loaded); err != nil { panic(err) }
    fmt.Println(loaded.Title)
    instant, err := time.Parse(time.RFC3339, "2026-10-17T08:00:00+08:00")
    if err != nil { panic(err) }
    fmt.Println(instant.UTC().Format(time.RFC3339))
    fmt.Println(2*time.Second + 500*time.Millisecond)
}

预期输出：

text
{"title":"学习 JSON"}
学习 JSON
2026-10-17T00:00:00Z
2.5s

time：时刻、时区与时长 ​

前置：上一节 time.Parse、UTC 与 Duration 的示例输出。时刻是时间轴上的一点，时区改变这个点的显示方式；时长则是经过多少时间。上例的 08:00 +08:00 与 00:00 UTC 是同一时刻。

查询 RFC3339 用法时，解析用 time.Parse(time.RFC3339, input)，输出用 instant.UTC().Format(time.RFC3339)；前者返回错误时不能继续使用解析结果。

这里 panic 只表示固定教学常量出错；处理用户输入时应返回并展示错误。Go 时间格式使用参考时间 2006-01-02 15:04:05，不是 YYYY-MM-DD。保存 API 时间统一 UTC RFC3339，显示时再转用户时区；Duration 是时间长度，time.Second 提供单位，不要把裸数字误当秒。

只含日期的输入可用 time.Parse("2006-01-02", "2026-10-17")；无时区布局默认解析到 UTC。业务要求当地时间时应使用明确的 Location 与 ParseInLocation，不要从服务器的部署地点推断用户时区。计算耗时用 time.Since(start)，比较时刻用 Equal、Before、After。

这里 start 应先由 start := time.Now() 记录。Time 包含时刻和位置等表示信息，判断同一时刻优先用 Equal；不要仅因两个 Time 的 == 为 false 就认定它们代表不同时间。

练习：将示例时区改为 +09:00，预期 UTC 为前一天 23:00。显示时区变化不代表存储的时间点能随意平移。

文本输入用 strings.TrimSpace 清掉首尾空白；strconv.Atoi 将命令行字符串转 int，并检查错误。不要用 JSON 反序列化代替简单整数解析，也不要忽略无法转换的 ID。

练习与自检 ​

先不运行上面的程序：预测 hidden 是否出现在 JSON 中，UTC 输出为什么比原时间少八小时。再把 Title 改为未导出的 title，运行并观察结果。预期 JSON 不再包含 title 键；修改后也要相应调整构造与读取字段名。

参考解法

encoding/json 只处理导出字段；标签不能改变可见性。UTC 转换改变显示的时区，不改变同一时刻。恢复大写字段后再运行，输出应恢复。对业务输入的解码错误应显式处理，不能继续使用零值覆盖持久化数据。
