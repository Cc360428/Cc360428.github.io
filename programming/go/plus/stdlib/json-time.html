Go JSON 与时间：字段存在性、时区与存储 ​

前置：文件与字节流与结构体和指针。持久化一条学习记录时，需要同时决定字段的对外名称、值的缺失语义和时间的表示方式。读取同一串 JSON 并不保证每个调用者都能恢复相同的业务含义。

编码契约与导出字段 ​

默认结构体编码按导出字段和 json 标签选取成员。标签改变键名，json:"-" 忽略字段。普通未导出字段不会因为加了标签就出现在 JSON 中。嵌入字段还受层级与名称冲突规则影响；类型自己实现 MarshalJSON 时，输出由实现决定。设计公共响应时，独立的响应类型能让字段改动接受评审，也能避免给内部数据意外增加一个导出字段就暴露给调用方。encoding/json

解码到结构体要传指针。默认未知键会被忽略；需要严格验证的 HTTP 边界可用 Decoder.DisallowUnknownFields。一个 Decoder 可以连续消费多个 JSON 值，协议若只允许一个，第一次成功后还要确认下一次解码得到 EOF。HTTP 请求边界

缺失、null 与零值 ​

假设每次解码都从一个新的零值结构体开始。普通 string 字段遇到省略、null、"" 时，三种输入最后都能表现为空串。*string 可以区分显式空串和 nil，但“键不存在”和“键存在且为 null”仍会得到 nil。若更新接口约定“省略表示保留，null 表示清空”，先解码到 map[string]json.RawMessage，用二元取值判断键存在，再判断其 JSON 值；或使用记录存在性的自定义解码类型。

请求是否提供键可能的更新语义
{}否保留现值
{"title":null}是按合同清空或拒绝
{"title":""}是收到显式空字符串，执行业务校验

解码错误可能发生在部分字段已写入之后。先解码到临时对象，完整校验成功再替换已保存的数据。输入字符串能解析、字段存在、业务允许是三个不同的检查。

时刻、时区与时长 ​

时刻是时间轴上的一点，时区是显示该点的解释规则。RFC3339 时间戳带有 UTC 或数值偏移，2026-10-17T08:00:00+08:00 和 2026-10-17T00:00:00Z 表示同一时刻。用 Time.Equal 比较时间点，用 In 或 UTC 改变显示位置。Go 的格式布局使用参考时间 2006-01-02 15:04:05。保存事件时间时可用 UTC RFC3339 或保留所需的小数秒精度；数值偏移不能恢复一个地区未来的夏令时规则。

Duration 表示经过的时间，time.Second 给它明确的单位。测本进程耗时，用 start := time.Now() 与 time.Since(start)；从文件解析的时间不含原进程的单调时钟读数。每日当地 09:00 的调度则需要日历日期和 IANA 时区；24*time.Hour 的持续时间在跨夏令时边界时可能抵达不同的当地钟点。无时区的日期使用 ParseInLocation 和明确位置，避免让部署机器决定用户所指的日期。time

下面只改变显示时区和字段表示，事件本身保持同一时刻。

go
package main

import (
    "encoding/json"
    "fmt"
    "time"
)

func main() {
    at, err := time.Parse(time.RFC3339, "2026-10-17T08:00:00+08:00")
    if err != nil { panic(err) }
    record := struct {
        Title string    `json:"title"`
        At    time.Time `json:"at"`
    }{"Go", at.UTC()}
    data, err := json.Marshal(record)
    if err != nil { panic(err) }
    fmt.Println(string(data))
    fmt.Println(at.Equal(record.At))
}
text
{"title":"Go","at":"2026-10-17T00:00:00Z"}
true

练习与自检 ​

把输入偏移改成 +09:00，保留当地钟点 08:00，先推算 UTC 日期。再为“标题修改”列出缺失、null、空串三项，写明现值分别如何变化。

参考解法

预期是前一天 23:00；若只对原有 at 调用 In，改变的则只是显示方式。若字段合同约定省略时保留、null 时清空、空串拒绝，三项测试要同时检查存在性、修改结果和失败后的原值。
