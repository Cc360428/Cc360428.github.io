契约与输入验证 ​

Task 含 id、title、category、status、created_at、updated_at。id 是正整数，title 去空白后 1–120 个 Unicode 码点，category 最多 40 个；时间为 UTC RFC3339Nano。LearningRecord 含 id、task_id、content、created_at，content 去空白后 1–2000 个码点。StatusChange 保存前后状态，由程序自动记录，不能当作心得写入。

方法与路径输入成功结果
POST /taskstitle、可选 category201，状态固定 todo
GET /taskscategory、status、q、page、page_size200，items/total/page/page_size
GET /tasks/正整数 id200，任务
PATCH /tasks/title/category 至少一个200，更新任务
DELETE /tasks/正整数 id204，关联记录同时删除
PUT /tasks/{id}/statusstatus200，更新任务与状态历史
POST /tasks/{id}/recordscontent201，心得记录
GET /tasks/{id}/recordsid200，items 按 id 正序
GET /tasks/{id}/changesid200，items 按 id 正序

状态允许 todo→doing、doing→todo/done、done→doing。todo 直接到 done 返回 409；重复提交当前状态返回 200，不重复记历史。PATCH 不接受 status，避免绕过转换校验。

错误统一为 {"error":{"code":"...","message":"..."}}。坏 JSON、null、未知字段、第二个 JSON 值、超出 1 MiB、无效字段/分页为 400；资源不存在 404；错误方法 405；非法转换 409；数据库操作失败 500。内部数据库错误写服务日志，不把内部细节原样返回客户端。

Gin 路由与中间件边界 ​

前置：net/http 请求模型。框架承接路由分发、JSON 响应和请求级中间件，输入、错误和资源生命周期仍由应用设计。本例 router 使用 gin.New，显式安装 Logger 与 CustomRecovery；恢复 panic 后统一返回 internal_error JSON，而不是默认文本错误。正常输入失败仍返回约定的 400/404/409，不能靠 panic/recover 表达所有失败。

HandleMethodNotAllowed、NoMethod 和 NoRoute 分别让错误方法与未知路径保持统一 JSON 格式。middleware 执行公共逻辑，失败时调用 Abort 后停止继续处理。不要把 gin.Context 保存给无明确退出条件的后台任务；只提取必要数据，并为任务安排自己的生命周期。数据库调用沿用请求 context，超时与关闭由服务入口配置。

旧 Gin 笔记中的 ping 对照例子已由 HTTP 衔接和本项目替代。需要理解框架差别时，比较两个项目的路由构建与 httptest：协议约定和失败断言由应用负责，使用框架不会自动保证其正确。

分类分页与 SQL 查询 ​

GET /tasks?category=Go&status=done&q=学习&page=1&page_size=20 同时筛选。category 精确匹配，q 为标题字面子串，status 必须是声明状态。默认第一页、每页 20，最多每页 100；零、负数、非整数和会导致偏移溢出的参数都拒绝。超出最后一页返回空 items，total 仍为匹配总数。

数据库表可以理解为具有约束的记录集合。tasks 的 id 为主键，records/changes 的 task_id 是指向任务的外键。SQL INSERT 新增、SELECT 查询、UPDATE 更新、DELETE 删除；WHERE 限制作用范围。示例用 ? 参数绑定用户输入，不能把标题直接拼进 SQL。q 用 SQLite 的 instr，输入 % 不会变成通配符。

排序固定 id 倒序后再 LIMIT/OFFSET，避免仅靠表自然顺序分页。此教学分页没有快照语义：翻页期间插入或删除会影响结果，不能把它用于要求精确遍历不变集合的场景。总数与列表也不是跨查询的一致快照。

Gin SQLite：事务回滚与外键 ​

状态修改和状态历史必须一起成功：开始事务 → 查当前状态 → 校验转换 → UPDATE tasks → INSERT changes → Commit。任一步失败就 Rollback；如果状态已变但日志没写入，用户复盘会看到不完整历史。事务中始终使用 tx，不混用 db 的另一条连接；提交错误也必须处理。

源码先登记 defer Rollback，成功 Commit 后的 Rollback 无实际修改。测试用临时触发器让历史插入失败，再读任务，验证状态仍是 todo；这比只测成功响应更能证明回滚边界。

外键 ON DELETE CASCADE 删除任务关联记录，但 SQLite 必须在实际连接上开启 foreign_keys。示例在驱动 DSN 中对每条连接设置 _pragma=foreign_keys(1)，并设置 busy_timeout；只在初始化时执行一次 PRAGMA，连接替换后可能丢配置。测试强制更换连接再删除，确认没有孤立记录。连接池限制为 1 是本地教学简化，不是高并发调优结论。
