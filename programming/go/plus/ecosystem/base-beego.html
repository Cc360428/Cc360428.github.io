Beego 工程维护：模块、MVC 与排错 ​

前置：HTTP 处理器和Modules。这篇维护参考针对已有 Beego MVC 工程。用一个只读图书接口从路由走到输出，能把旧代码里的三件事分开检查：请求是否命中路由、控制器是否接受参数、数据源是否返回记录。

模块与路由 ​

仓库 examples/go/beego-reader 固定使用 github.com/beego/beego/v2 v2.3.8。v2 的 Web 包位于 github.com/beego/beego/v2/server/web。先看 go.mod 和导入路径，再决定使用哪一份 bee 文档。旧项目的生成器版本、配置格式和 ORM 模型应分别核对。单独启动框架只会建立服务入口，还要把路径与控制器方法注册到实际处理请求的同一个路由器上。

go
app := web.NewHttpServerWithCfg(web.BConfig)
app.Router("/books/:id", &BookController{}, "get:Get")

:id 是路径参数的占位符。get:Get 将 HTTP GET 绑定到控制器方法。示例的服务入口和测试都调用同一 routes() 创建新的路由器，从而验证真实注册行为，又能隔离每次测试的路由状态。

MVC 中的输入、模型与响应 ​

控制器从 c.Ctx.Input.Param(":id") 取得文本，解析正整数后查询课程的单条固定记录。合法 ID、现有资源和错误返回各有独立含义。若换成数据库查询，未找到记录可以返回 404；连接不可达或查询失败属于依赖故障，不能伪装成“没有这本书”。本例没有数据库，因而可以单独检查框架映射和 JSON 合同。

输入决策可观察结果
GET /books/1ID 合法且记录存在200，{"title":"Go 入门"}
GET /books/abc 或 /books/0ID 无效400，{"error":"invalid id"}
GET /books/2ID 合法，记录缺失404，{"error":"book not found"}

ServeJSON 序列化 c.Data["json"]。状态必须在写正文之前设置，失败输出仍使用相同媒体类型。页面项目的 view 可能渲染模板，JSON API 则直接生成协议表示；业务判断仍应写在读者能追踪和测试的位置。

路由、控制器和监听入口
go
package main

import (
	"log"
	"net/http"
	"strconv"
	"time"

	"github.com/beego/beego/v2/server/web"
)

type BookController struct{ web.Controller }

func (c *BookController) Get() {
	id, err := strconv.ParseUint(c.Ctx.Input.Param(":id"), 10, 64)
	switch {
	case err != nil || id == 0:
		c.Ctx.Output.SetStatus(http.StatusBadRequest)
		c.Data["json"] = map[string]string{"error": "invalid id"}
	case id != 1:
		c.Ctx.Output.SetStatus(http.StatusNotFound)
		c.Data["json"] = map[string]string{"error": "book not found"}
	default:
		c.Data["json"] = map[string]string{"title": "Go 入门"}
	}
	if err := c.ServeJSON(); err != nil {
		log.Print(err)
	}
}

func routes() http.Handler {
	app := web.NewHttpServerWithCfg(web.BConfig)
	app.Router("/books/:id", &BookController{}, "get:Get")
	return app.Handlers
}

func main() {
	server := &http.Server{Addr: "127.0.0.1:8082", Handler: routes(), ReadHeaderTimeout: 5 * time.Second}
	log.Fatal(server.ListenAndServe())
}

ORM 模型和生成代码 ​

维护旧 ORM 时，orm:"rel(fk)" 与 orm:"reverse(many)" 表达外键与反向集合，双方字段方向要与数据库真实约束一致。json 标签决定编码形式，ORM 标签交给持久化层，两者无法替代。生成模型后应检查字段、空值、索引、事务和实际 SQL，再在专用测试库验证迁移。这里的只读控制器无需 bee 或数据库。

按请求经过的阶段定位 ​

端口不可达先核对进程和监听地址；端口可达而路由 404，再核对方法、路由前缀和实际运行的版本。若控制器已经返回业务 JSON，则可用其状态与字段继续区分输入错误和找不到数据。旧工程出现 QueryTable 找不到表时检查注册、schema 与实际连接库。Swagger 生成失败可先查注解与生成器目录，浏览器跨域则需观察预检响应和来源策略。Beego v2 Web API

测试和练习 ​

进入 examples/go/beego-reader 运行 go test -count=1 -v .。通过 httptest.NewRequest 和真实 Beego 路由处理请求，断言状态、JSON 媒体类型和对应字段。另可 go run . 后访问 http://127.0.0.1:8082/books/1。练习：假设把错误的 ID 同样返回 404，客户端将无法区分“修正请求”和“该书没有收录”，已有测试会指出哪一项合同改变。

路由与控制器测试
go
package main

import (
	"encoding/json"
	"net/http/httptest"
	"strings"
	"testing"
)

func TestBookRoute(t *testing.T) {
	app := routes()
	for _, tc := range []struct {
		id, field, want string
		status          int
	}{
		{"1", "title", "Go 入门", 200},
		{"abc", "error", "invalid id", 400},
		{"0", "error", "invalid id", 400},
		{"2", "error", "book not found", 404},
	} {
		t.Run(tc.id, func(t *testing.T) {
			w := httptest.NewRecorder()
			app.ServeHTTP(w, httptest.NewRequest("GET", "/books/"+tc.id, nil))
			if w.Code != tc.status || !strings.HasPrefix(w.Header().Get("Content-Type"), "application/json") {
				t.Fatalf("status=%d, type=%s, body=%s", w.Code, w.Header().Get("Content-Type"), w.Body)
			}
			var body map[string]string
			if err := json.Unmarshal(w.Body.Bytes(), &body); err != nil || body[tc.field] != tc.want {
				t.Fatalf("body=%v, err=%v", body, err)
			}
		})
	}
}
