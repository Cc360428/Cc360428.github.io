C++ 迭代器、区间与容器修改 ​

已能创建 std::vector<int> 并遍历元素后，可以把“访问哪些元素”和“对它们做什么”分开。库存汇总既要查找、统计，也要删除无效记录。先确认算法要求的区间，再看容器操作会使哪些借用失效。

半开区间和结束位置 ​

标准算法通常接收 [first, last)，first 指向第一个待处理元素，last 只标记结束。begin() == end() 表示区间为空。查找时 std::find(first, last, value) 返回匹配元素的迭代器，找不到时返回 last。每次解引用前都要先排除结束位置；容器为空时同样适用。

迭代器支持的操作由类型决定。std::vector 的随机访问迭代器可以做 it + n，std::list 的双向迭代器只能逐步前进或后退。std::sort 要求随机访问迭代器，链表排序可使用它自己的成员函数。选算法之前要同时看迭代器能力和元素需要的操作。

两步筛选各改变什么 ​

std::remove_if 把要保留的元素按原有相对顺序集中到区间前部，返回这个有效前缀的尾后迭代器。容器的元素个数仍相同；尾部元素仍存在，其值不能用来识别原先被筛掉的记录。vector.erase(new_end, end()) 才销毁实际的尾部元素，改变 size()。在 C++20 中，std::erase_if(vector, predicate) 可以将这两步合成一次调用。标准草案中 remove 算法的契约 · vector 的插入与擦除

修改容器后要重新判断之前保存的位置是否有效。非空区间的 vector::erase 会使擦除点及其后的迭代器和引用失效。如果追加导致重新分配，旧元素的地址、引用和迭代器都失效。reserve(n) 可为一段已知规模的追加提前留出空间，但容器的大小不变；留出容量后也不能用下标访问尚未创建的元素。vector 的容量规则

实验：保留及格成绩 ​

保存为 keep_scores.cpp。同时包含两个相邻的未达标成绩，可以检出“边遍历边删除，却额外前进了一步”的错误。

cpp
#include <algorithm>
#include <cassert>
#include <vector>

void keep_passing(std::vector<int>& scores) {
    auto kept_end = std::remove_if(scores.begin(), scores.end(),
                                   [](int score) { return score < 60; });
    scores.erase(kept_end, scores.end());
}

int main() {
    std::vector<int> scores{59, 0, 60, 98};
    keep_passing(scores);
    assert((scores == std::vector<int>{60, 98}));
    assert(std::find(scores.cbegin(), scores.cend(), 99) == scores.cend());

    std::vector<int> none{1, 2};
    keep_passing(none);
    assert(none.empty());
    keep_passing(none);
    assert(none.empty());
}

执行 c++ -std=c++17 -Wall -Wextra -Werror keep_scores.cpp -o keep_scores，再运行 ./keep_scores。不定义 NDEBUG 时，三个输入状态都应通过，退出 0。若删掉 erase，首个断言就会失败，因为向量仍有四个元素。

自测。 如果必须逐个擦除，遇到要删的元素就接收 it = scores.erase(it)，保留元素才执行 ++it。比较两个写法的移动量：逐个从向量前部擦除可能反复搬移后继元素，两步筛选只需线性扫描并处理尾部。接着看库存汇总项目，判断何时应借用输入记录，何时应持有一份独立的数据。
