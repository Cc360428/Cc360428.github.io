Lua 的 table：键、连续序列与共享引用 ​

Lua 用 table 表示配置、数组和记录。三者拥有同一种运行时类型，区别在于调用方约定哪些键合法、遍历顺序是否有意义、哪些值代表缺失。本页使用普通 table，没有元表介入。

缺键、假值和数字键 ​

给不存在的键取值会得到 nil，给已有键赋 nil 会删除它。值 false 会保留，因此“存在这个设置”和“启用这个设置”需要两个不同的判断。t.name 等价于 t["name"]；数字键 1 与字符串键 "1" 是两个键。实现配置默认值时，只为 nil 提供默认值，保留用户显式选择的 false。

连续序列有一个边界 ​

若正整数键从 1 连续到 n，后面没有项，就可以把它当作长度为 n 的序列。ipairs 从 1 依次读取，在第一个 nil 处结束，遇到 false 仍会继续。pairs 用于遍历所有现有键，普通 table 的键顺序没有保证。#t 在带空洞的表上只能给出某个边界，无法推出有效元素总数。数据有位置而且允许空值时，应另存明确长度，或使用占位值。

将下例保存为 tables.lua 并运行 lua tables.lua。

lua
local settings = {enabled = false, [1] = "first", [3] = "third"}
assert(settings.enabled ~= nil and not settings.enabled)
assert(settings["1"] == nil)
local visited = 0
for _ in ipairs(settings) do visited = visited + 1 end
assert(visited == 1)

local keys = 0
for _ in pairs(settings) do keys = keys + 1 end
assert(keys == 3)
settings[2] = false
assert(#settings == 3)
settings.enabled = nil
assert(settings.enabled == nil)
print("table checks passed")

复制变量会复制哪一层 ​

local b = a 让两个名字指向同一张表。用 for k,v in pairs(a) do b[k] = v end 写入一张新表，则只复制外层键值；若某项是 table，复制过去的仍是指向它的引用。把 a.theme 重新绑定到另一张表和修改 a.theme.color 是两种不同的改动。

练习时令 a = {theme = {color = "blue"}}，浅复制到 b。把 a.theme.color 改成 red 后 b 也看见 red；把 a.theme 换成 {color = "green"} 后 b 仍持有旧表，读到 red。需要隔离修改时，可仅复制需要独立修改的那一层。若输入允许共享或环，递归深复制还须定义如何处理身份和循环。Lua 参考手册的值与表
