Coturn 搭建 ​

Coturn ​

  • github

以下保留Coturn4.5.1.3的历史操作与输出，未在本轮部署。出现的公网地址和凭据仅用于识别旧记录，复制时必须替换；测试段另一个地址不是下方配置启动成功的证据。新环境按官方配置注释核对选项与防火墙。

需要下载文件 ​

shell
sudo apt-get install libssl-dev
sudo apt-get install libevent-dev
sudo apt-get install libpq-dev
sudo apt-get install mysql-client
sudo apt-get install libmysqlclient-dev
sudo apt-get install libhiredis-dev

生成证书 ​

shell
openssl req -x509 -newkey rsa:2048 -keyout /etc/turn_server_pkey.pem -out /etc/turn_server_cert.pem -days 365 -nodes

这是自签名测试证书；客户端信任链仍需单独处理，不能据此承诺turns:可用。-nodes使用ASCII短横线并生成未加密私钥，文件权限应限制到服务账号。

查看主机 ​

ifconfig

shell

192.0.2.10
192.0.2.20

修改配置文件 ​

以下只保留带注释的一份历史配置；地址、用户及口令必须替换。它与下方启动日志来自不同旧记录，不应拼成同一次成功部署。

注释单独成行：4.5.1.3 的配置读取实现只跳过以 # 开头的注释行，不能把行尾说明附在地址、网卡名或凭据后面。

Empty cli-password ... telnet cli interface is disabled表示管理CLI被禁用，不等于TURN中继必然启动失败；不需要CLI时可明确设置no-cli，不要为消除提示启用弱口令管理入口。

shell
# 与前面 ifconfig 查到的网卡名称一致
relay-device=eth0
# 本机网卡实际拥有的内网 IP
listening-ip=192.0.2.10
listening-port=3478
tls-listening-port=5349
relay-ip=192.0.2.10
# 公网/内网映射
external-ip=192.0.2.20/192.0.2.10
realm=example.invalid
relay-threads=50
lt-cred-mech
cert=/etc/turn_server_cert.pem
pkey=/etc/turn_server_pkey.pem
pidfile=/var/run/turnserver.pid
min-port=49152
max-port=65535
# 用户名和密码，创建 IceServer 时使用
user=example-user:example-user
cli-password=qwerty

若公网IP直接配置在网卡上，可绑定该公网地址；若位于NAT后则绑定本机私网地址并声明公网映射，不能绑定网卡并未拥有的公网IP。除3478、5349监听端口外，还要按实际传输配置放通并正确映射49152–65535中继端口；仅开放STUN监听端口不能保证TURN媒体可达。

启动 ​

下面两条命令是历史启动方式，不是必须连续执行的步骤。第二条显式读取 /etc/turnserver.conf；旧日志却读取 /usr/local/etc/turnserver.conf，realm 也分别出现 Guangdong、ylbs 与上文 example.invalid。新环境应选定一份配置与 realm 后再启动，不能把这些旧值当作已核实的一致配置。

  • turnserver -o -a -f --user=example-user:example-user -r Guangdong
  • turnserver -v -r ylbs -a -o -c /etc/turnserver.conf

监听成功到中继可用还有哪些关卡 ​

Coturn监听3478或5349是连接入口，分配的中继地址和端口才承载对应中继流量。位于NAT后的主机必须公布正确公网映射，并让中继端口范围按实际配置可达；客户端拿到relay候选后，仍需执行候选对检查和实际收发。参见Coturn官方配置注释。

排查按层保留证据：进程监听、认证分配结果、返回的relay地址、候选对选择、双向收发。仅看到启动日志或候选列表不能跳过后面步骤。本文保留历史命令，没有执行部署，旧地址与口令不是本轮可用配置。
