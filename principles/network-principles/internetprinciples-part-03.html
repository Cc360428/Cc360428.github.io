计算机网络原理（04735） · 应用层：从域名到服务至协议参考 ​

按“分层与性能 → 链路 → IP 与路由 → 传输 → 应用”的顺序理解一次请求，再补充无线与安全。历史课程中的电路交换、PPP、经典共享以太网等保留为原理对照，不与现代网络部署混写。

应用层：从域名到服务 ​

DNS 查询与缓存 ​

下图假设递归解析器没有可用缓存。根和顶级域服务器通常返回委派线索，解析器继续查询权威服务器，最后缓存答案；后续查询在TTL允许范围内可直接使用缓存。

DNS 按分布式层级管理名字和资源记录。主机通常向递归解析器查询，解析器在缓存未命中时向根、顶级域和权威服务器等逐步取得信息；有缓存或已有委派信息时，无需每次从根开始。

DNS 不只返回 IP，常见记录有 A、AAAA、CNAME、MX 等。域名从右向左形成层级；例如 www.example.com 的顶级域是 com，不能把多标签的 com.cn 与独立顶级域混淆。

HTTP、连接与状态码 ​

HTTP 定义请求方法、字段、状态码与内容语义。HTTP/1.1 使用文本形式的起始行与首部，HTTP/2 使用二进制帧，HTTP/3 基于 QUIC；不能把所有 HTTP 都说成先建立 TCP。

GET 读取资源表示，HEAD 获取类似 GET 的首部而不返回内容，POST 提交处理，PUT 更新目标资源表示，OPTIONS 查询通信选项。持久连接减少重复建连，实际往返次数取决于协议、对象数、缓存和并发，不能孤立记成固定 3/4/8 RTT。

类别 / 状态含义
1xx / 2xx / 3xx信息性 / 成功 / 重定向相关
4xx / 5xx客户端错误 / 服务端错误
200 / 301 / 304成功 / 永久重定向 / 缓存表示未修改
400 / 401 / 403 / 404请求无效 / 需认证 / 禁止 / 未找到
415不支持的媒体类型，不是 451
500 / 502 / 503服务端错误 / 网关上游错误 / 暂不可用

HTTP 无状态不等于服务器无法保存会话。Cookie 由响应 Set-Cookie 设置、浏览器按作用域通过 Cookie 发送，可用于会话标识与偏好；不应直接保存明文密码。会话 Cookie 的恢复行为受浏览器会话恢复等机制影响，不能一概说关闭窗口就彻底清除。

邮件、文件传输与 Socket ​

SMTP 负责邮件提交/传输，POP3、IMAP 用于收取与管理；MIME 表达附件和多媒体。端口、TLS 与认证取决于具体服务模式，不把所有邮件连接都固定为明文 25/110。

FTP 把控制与数据连接分开，控制常用 21；主动与被动模式的数据连接不同，不能断言数据永远走 20。P2P 中节点可兼有请求与服务角色，实际应用也可能依赖中心协调。

Socket 是应用使用网络能力的接口。TCP 服务端常见顺序为 socket → bind → listen → accept → 收发 → close，客户端为 socket → connect → 收发 → close；UDP 常用 sendto/recvfrom。一次 send/recv 不保证刚好对应一个应用消息。

无线、移动性与切换 ​

终端从AP1转到AP2后，先判断二层接入是否完成，再判断IP是否变化。保持相同IP也不能保证没有短时丢包；IP变化后原有传输连接能否继续，取决于协议和部署支持。

无线链路要处理衰减、干扰、多径和隐藏终端等问题。IEEE 802.11 的 AP 与终端组成基本服务集，帧包含管理、控制、数据等类型；无线接入并不意味着设备正在移动。

移动性涉及位置、可达地址与连接连续性。传统 Mobile IP 用归属网络、归属代理和转交地址等机制说明“位置变化而维持标识”的思路；它不等于所有现代蜂窝或 Wi-Fi 漫游的具体实现。切换时要区分链路重关联、IP 变化和应用重连。

安全：加密、认证与网络边界 ​

机密性、完整性与身份 ​

安全目标应分别验证。加密隐藏内容，消息认证验证内容和持有密钥的一方，证书验证则帮助绑定公钥与预期身份；其中任一成功都不能自动证明业务授权正确。

查看图表代码

对称加密用于共享密钥下的数据保护；公钥机制可用于身份认证、密钥协商或签名，具体算法用途不同。哈希本身不证明消息来自可信发送方，MAC 依赖共享秘密，数字签名结合私钥签名与公钥验证。

证书把公钥与身份联系起来，验证还包括信任链、有效期及目标名称等条件。历史课程提到 DES、MD5、SSL 等，不应直接作为现代安全配置建议。

TLS、IPsec 与防火墙 ​

TLS 提供传输保护，握手、密钥派生和认证流程因版本而异；旧 RSA 预主密钥流程不能代替 TLS 1.3 的协商机制。具体细节按协议版本学习。

IPsec 是网络层安全体系，包含 ESP/AH 等协议与传输/隧道模式；VPN 的实现和安全性取决于选定协议、配置与密钥管理，不能用“某个名字最安全”作结论。

防火墙可按无状态规则、连接状态或应用代理等方式过滤流量；检测系统用来发现异常。允许端口不代表应用已经有正确的鉴权，启用加密也不代表所有授权问题都已解决。

用一次请求串联复习 ​

  1. 画出客户端、AP/交换机、网关、路由器和服务端，标出每跳 MAC 与端到端 IP。
  2. 给定地址和掩码计算子网，按最长前缀选择下一跳。
  3. 解释 DNS 命中/未命中、TCP 或 QUIC 建连、TLS 与 HTTP 各自做什么。
  4. 区分 DNS 失败、连接失败、认证失败、上游超时和吞吐瓶颈，不把所有问题归为“网络不好”。
  5. 用一份抓包核对序号、确认和重传，用实际时延数据区分排队、传播与发送开销。
