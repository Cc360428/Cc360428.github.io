🐧 Linux、Kubernetes 与 Helm 命令手册 ​

从日常操作到线上排障的任务导向手册。先理解命令的读取范围和写入范围，再在目标环境执行。

一、学习路径 ​

阶段文档适合场景
1Linux 基础命令文件、文本、权限、进程、服务、网络、磁盘、归档和软件包
2Linux 进阶命令管道处理、日志分析、性能诊断、systemd、SSH 和故障定位
3Kubernetes 基础命令集群上下文、资源查询、部署、日志、伸缩和发布
4Kubernetes 进阶命令JSONPath、调试容器、RBAC、Server-Side Apply 和故障排查
5Helm 基础与进阶Chart、Release、模板、依赖、升级回滚、OCI 和安全发布

Kubernetes 的架构、API、工作负载、网络、存储和安全原理放在独立的 Kubernetes 知识手册 中；本目录聚焦可以直接执行的命令和排障流程。

二、示例约定 ​

文档中的尖括号表示必须替换的变量，不要原样输入：

bash
ssh <user>@<host>
kubectl -n <namespace> get pod <pod-name>
helm upgrade --install <release> <chart> -n <namespace>

常用占位符：

占位符含义示例
<user>Linux 或远端用户名alice
<host>主机名或 IP10.0.1.20
<namespace>Kubernetes 命名空间production
<pod-name>Pod 名称api-7c8d9f6b5-x2abc
<release>Helm Release 名称api
<chart>Chart 路径、仓库引用或 OCI 地址./chart

三、执行前的安全基线 ​

  1. 确认身份、主机和目录：id; hostname; pwd。
  2. Kubernetes 操作先确认上下文和命名空间：kubectl config current-context、kubectl config view --minify。
  3. 先读后写：先用 ls、find、kubectl get、helm diff 或 helm template 看清目标。
  4. 删除、覆盖、递归修改和强制操作必须逐项确认目标，避免未引用变量和宽泛通配符。
  5. 生产变更保存命令、时间、操作者、变更前后状态和回滚方案。
  6. 不把密码、Token、私钥或完整 Secret 粘贴到终端历史、工单和聊天中。

高风险命令

rm -rf、chmod -R、chown -R、dd、mkfs、kubectl delete、kubectl replace --force、helm uninstall 等操作可能造成不可恢复的数据或服务损失。示例出现这些命令时，必须先执行相邻的只读检查，并确认备份和回滚路径。

五、命令帮助的优先级 ​

系统版本、发行版和工具版本会影响可用参数。遇到差异时，按以下顺序确认：

bash
# 1. 查看工具版本
uname -a
kubectl version --client
helm version

# 2. 查看本机命令帮助
man <command>
<command> --help
kubectl explain <resource>

# 3. 再查对应版本的官方文档

本手册给出安全、通用的 GNU/Linux 和 Kubernetes 操作方式，但不能替代目标系统的变更规范和权限审批。
