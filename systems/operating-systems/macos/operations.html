macOS：配置变更、排障与恢复 ​

任务维护、日志与恢复 ​

维护macOS 用户快照作业前先保存macOS 14/15、Zsh 路径、用户域与文件权限，恢复后以sw_vers/uname/id 输出、Label 和后台退出状态验收。具体配置见配套示例。

教学版本族：macOS 14/15，Apple Silicon 与 Intel；系统自带 BSD 工具、Zsh 5.9 语义；不承诺所有小版本。核对日期2026-10-17，不称为2026最新版。示例未执行，配置与命令需按目标环境验收。macOS只交付理论，不纳入原生运行验收。

更新与软件来源 ​

macOS 更新应区分系统更新与第三方包。先记录应用来源、版本、签名与备份，读者日后再使用系统更新界面。Homebrew 是第三方包管理器，Intel 与 Apple Silicon 的常见前缀不同，不能覆盖成固定全局 PATH。本课不提供远程脚本下载即执行，也不把旧软件清单当作推荐安装集合。

用户配置恢复 ​

macOS 配置恢复先备份具体文件，记录更改前后差异与应用版本。用户偏好、应用缓存、日志是不同对象，删除缓存不等于卸载；GoLand2021.2 的历史目录不适用于每个版本。只恢复任务拥有的文件，恢复后仍需日后在真实应用检查，禁止靠删除整个 Library 排错。

作业撤回与清理 ​

macOS 快照清理先停止后续触发，若读者自行注册用户作业，应在相同用户域撤回 Label，再确认不再运行。只删除新建专用目录内脚本、plist 和自己保存的输出；不删除系统 LaunchDaemons 或原用户日志。未注册时无需操作 launchd，报告是标准输出时无需清理系统数据。

练习与参考解答 ​

题目：读者只复制snapshot.zsh并把stdout保存为自己专用目录的report.txt，未bootstrap plist。之后想撤回示例。哪些对象需要清理？能否删除~/Library/LaunchAgents或整个Library？

参考解答：没有注册launchd作业，所以无需bootout。核对专用目录完整绝对路径和所有者后，只删除自己复制的snapshot.zsh及report.txt；如果也复制了plist/requirements，只删除这些确切文件。LaunchAgents与整个Library可能属于其他应用，不能删除。若目录原本已有其他文件，保留目录和其他文件；原系统工具没有被修改，不需要回滚。

核对资料 ​

  • Apple 中文 SIP 安全说明
  • Apple 文件访问控制
  • Apple launchd 编程指南（归档）

历史参照：原macOS 软件清单与 GoLand 卸载记录。GoLand2021.2残留目录只对旧版本适用；新课解释偏好/缓存/日志不同，不复制软件推荐或泛化删除Library。

图形应用运行时与精确卸载对象 ​

macOS 终端找到 Java 为何 Eclipse 失败，GoLand 卸载能删除 Library 吗？ macOS 图形应用的启动环境与终端 Shell 的 PATH 不能视为相同来源。Eclipse 找不到 Java 时，应先记录应用版本、架构、选定运行时及实际启动配置，而不是改全局 PATH 或关闭系统保护。旧例的 eclipse.ini 用 -vm 指定运行时，且它必须置于 -vmargs 前；具体可接受路径形式仍需核对匹配版本的启动器说明。旧 JDK14 路径与 launcher jar、重复参数的完整 ini 撤回为通用配置，不推荐据此安装旧运行时。Eclipse 启动器参数

应用包、Application Support 中的配置/插件、Preferences 中的偏好和 Logs 中的日志有不同用途。移到废纸篓不等于这些对象同时删除；清缓存也不等于卸载。旧 GoLand2021.2 目录仅对应该历史版本，不能按名字模糊匹配后删除整个 Library。应先记录应用标识与确切路径，备份需要的配置和许可资料，再按应用文档决定删除范围；出现其他版本或共享数据时保留并调查。

旧软件清单里的远程桌面、播放器、代理、SSH 和绘图工具仅是曾用名称，不是当前推荐与依赖清单。macOS 理论仍属于本课程。

后台任务、路径与权限排障 ​

本节沿sw_vers/uname/id 输出、Label 和后台退出状态定位失败层；先确认macOS 14/15、Zsh 路径、用户域与文件权限，与配套示例逐项对照，再选择最小修复。

Operation not permitted 定位 ​

macOS Operation not permitted 不等于必须 sudo。先确认操作对象、完整路径、调用程序和会话，再区分所有权、ACL、TCC、SIP、只读卷等原因；保存最小错误信息，避免导出私有文件名。课程快照不触及隐私目录，若仍失败，先检查系统工具是否存在与运行环境，不以关闭安全能力作为修复。

作业没运行的证据 ​

macOS launchd 排错先核对域、Label 和路径。未装载、参数路径不存在、退出非零与运行后立即完成是不同情况；短任务不常驻是预期行为。plist XML 能解析只说明文档结构，不能证明 launchd 接受、当前用户有权限或命令可用。

进程与端口证据 ​

macOS 进程排错先记录 PID、所属用户、启动时间与程序路径。端口监听者只是线索，PID 会复用，不能按旧截图直接 kill。先判断是否应由所属管理器优雅停止，再在授权范围操作；旧工具笔记的 kill -9 和递归 chown 是现场写操作，不是通用第一步。

练习与参考解答 ​

题目：一份错误记录显示用户作业立即退出0，但进程列表里没有常驻进程；另一份显示退出1且脚本路径拼错。分别判断是否失败，以及应该先检查哪项证据。

参考解答：本例是短快照，退出0后不常驻符合契约，不能因找不到进程判失败；继续核对三个快照字段的采集记录即可。第二份是执行路径错误，应先核对用户域、Label、ProgramArguments的绝对路径与文件存在性，再检查脚本错误摘要。两者都不能通过把KeepAlive改成true来证明修复，XML可解析也不能替代作业退出证据。

核对资料 ​

  • Apple 中文 SIP 安全说明
  • Apple 文件访问控制
  • Apple launchd 编程指南（归档）

历史参照：原macOS Eclipse 指定 JDK 14 路径。Eclipse JDK14路径只对应旧应用配置；吸收应用启动环境与终端PATH不同的教训，不继承旧JDK安装方案。

历史参照：原macOS 文件、进程与终端操作。已读递归chown、zsh加载bash_profile、kill -9、mdfind与远程安装脚本；新课程按权限层次、解释器配置与优雅停止解释，不把现场写操作当通用第一步。

终端成功但后台失败的复盘 ​

以下演练将macOS 用户快照作业的变更、失败证据和恢复验收串起来；先熟悉配套示例中的macOS 14/15、Zsh 路径、用户域与文件权限。演练未执行。

故障场景与影响 ​

相同命令在 Terminal 中成功，作为 LaunchAgent 后没有产生预期文件。

先记录首次异常时间、受影响对象和最近变更，区分个别对象失败与整条管理链路异常。以下是排查演练，不是已发生事故的实测记录。

按证据定位原因 ​

  1. 核对任务 label、所属登录用户与运行域，确认配置确实被该会话加载。
  2. 比较解释器绝对路径、参数、工作目录和日志路径；不要依赖终端初始化文件补齐 PATH。
  3. 检查退出状态与指定时间窗口日志；若访问受保护目录，再核对隐私授权与实际执行程序身份。

恢复步骤与验收 ​

只修正任务声明中缺失的路径、环境或必要授权，保留原配置和日志；恢复到已验证的任务版本，不用提升整个任务权限替代诊断。

验收：在真实后台上下文触发一次，核对退出状态与目标文件，再检查重新登录后的任务行为。交互终端成功只作为对照，不能作为后台验收。

将触发条件、直接原因、修复动作、恢复证据和后续检查写入同一份复盘，明确每项后续工作的负责人。机制参考：官方说明。

分层推理自检 ​

问题：终端有权限、后台报拒绝，是否证明系统有缺陷？答案：两者程序身份、会话、PATH 与 TCC 授权可能不同。先解释读的是什么、哪个进程读取、在哪个用户域，再比较证据；管理员角色不能替代这三项。

独立复习任务 ​

不运行任何命令，画出 Finder、终端、Zsh、launchd 与文件系统五个对象，写出快照脚本每一行结果的生产者。再说明对用户目录、系统目录和 APFS 卷的判断分别需要哪种证据。

参考解答与范围 ​

Finder 管图形文件入口，终端托管会话，Zsh 解释语法，launchd 管理生命周期，文件系统保存对象。快照来自 sw_vers、uname、id；这三项不能回答 TCC、磁盘完整性与备份恢复。后续可单列企业设备管理、签名公证与恢复演练。
