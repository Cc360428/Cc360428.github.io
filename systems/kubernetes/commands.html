kubectl 常用命令与操作边界 ​

Kubernetes 命令速查 ​

安全开场 ​

bash
kubectl config current-context
kubectl cluster-info
kubectl config view --minify -o jsonpath='{..namespace}{"\n"}'
kubectl auth whoami

生产写操作显式带 --context=<context> -n <namespace>；先查询对象与 Owner，再 dry-run/diff。

发现与查询 ​

bash
kubectl api-resources --sort-by=name
kubectl explain deployment.spec.strategy --recursive
kubectl version
kubectl -n demo get pods -o wide
kubectl -n demo get deployment,service,ingress
kubectl -n demo get pods -l app=web --show-labels
kubectl -n demo get pods --field-selector=status.phase=Pending
kubectl -n demo describe pod <pod>
kubectl -n demo get events --sort-by=.lastTimestamp
kubectl get pods -A --field-selector='status.phase!=Running'

应用与发布 ​

bash
kubectl apply --dry-run=client -f manifests/
kubectl apply --server-side --dry-run=server -f manifests/
kubectl diff -f manifests/
kubectl apply -f manifests/
kubectl -n demo set image deployment/web web=registry.example.com/web:2.4.1
kubectl -n demo rollout status deployment/web --timeout=5m
kubectl -n demo rollout history deployment/web
kubectl -n demo rollout undo deployment/web --to-revision=3
kubectl -n demo wait --for=condition=available deployment/web --timeout=5m

HPA 管理的对象不要手工长期改副本；rollout undo 不回滚 ConfigMap、Secret 和数据库。

日志与调试 ​

bash
kubectl -n demo logs <pod> -c <container> --since=15m --timestamps
kubectl -n demo logs <pod> -c <container> --previous
kubectl -n demo exec -it <pod> -c <container> -- /bin/sh
kubectl -n demo port-forward service/web 8080:80
kubectl -n demo debug -it pod/<pod> --target=<container> \
  --image=registry.k8s.io/e2e-test-images/busybox:1.29-4 --profile=general
kubectl get --raw='/readyz?verbose'

exec 和临时容器是远程执行能力；节点 sysadmin 调试权限更高，必须走审批并清理。

网络与存储 ​

bash
kubectl -n demo get service web -o yaml
kubectl -n demo get endpointslice -l kubernetes.io/service-name=web -o wide
kubectl -n demo get ingress,httproute,networkpolicy
kubectl -n demo exec <client-pod> -- nslookup web
kubectl -n demo exec <client-pod> -- wget -S -O- http://web:80/readyz
kubectl -n demo get pvc
kubectl get pv,storageclass

删除 PVC/PV 前核对 ReclaimPolicy、后端卷 ID 和可恢复备份。

调度、资源与权限 ​

bash
kubectl get nodes --show-labels
kubectl describe node <node>
kubectl -n demo get pods --field-selector=spec.nodeName=<node> -o wide
kubectl top nodes
kubectl -n demo describe hpa web
kubectl auth can-i --list -n demo
kubectl auth can-i get pods --as=system:serviceaccount:demo:web -n demo

节点维护 ​

bash
node='worker-01'
kubectl get pods -A --field-selector="spec.nodeName=$node" -o wide
kubectl get pdb -A
kubectl cordon "$node"
kubectl drain "$node" --ignore-daemonsets --delete-emptydir-data --timeout=20m
# 完成维护并验证节点健康后
kubectl uncordon "$node"

drain 会驱逐工作负载并删除 emptyDir 数据；不要随意用 --disable-eviction 绕过 PDB。

删除前检查 ​

bash
kubectl -n demo get <kind> <name> -o yaml
kubectl -n demo delete <kind> <name> --dry-run=server

灾难级操作

强制零宽限删除、批量 --all 删除、删除 Namespace/PVC/PV、清空 Finalizer、直接修改 etcd 可能造成重复实例或永久数据丢失。本页不提供这些可复制命令；必须使用经审批的对象专用灾备 Runbook。

详细语义见 kubectl 基础、kubectl 进阶和排障手册。

kubectl 基础命令 ​

kubectl ​

简介 ​

  • kubectl 是 Kubernetes 命令行工具，用于与 Kubernetes 集群进行交互和管理。
  • 它可以用来部署应用程序，管理集群资源（例如 Pod、Service 和 ReplicaSet 等），
  • 诊断和调试问题，以及执行其他与 Kubernetes 相关的任务。通过 kubectl，您可以在命令行界面中执行所有 Kubernetes API 操作，并对集群的状态进行操作。
  • kubectl 是使用 Go 语言编写的开源软件，需要匹配版本的客户端、目标集群 kubeconfig、网络和所需授权；本机不必运行 Kubernetes 节点。

基础命令 ​

下面按查询、变更与远程执行区分常用命令，占位符须替换为已确认对象。

  1. 获取集群信息：

    bash
    # 查看 Kubernetes 集群信息
kubectl cluster-info

# 查看节点列表
kubectl get nodes

  2. 获取资源对象信息：

    bash
    # 获取 Pod 列表
kubectl get pods

# 获取 Service 列表
kubectl get services

# 获取 Deployment 列表
kubectl get deployments

# 获取 ReplicaSet 列表
kubectl get replicasets

  3. 创建、更新和删除资源对象：

    bash
    # 通过 YAML 文件创建资源对象
kubectl create -f <YAML_FILE>

# 更新资源对象
kubectl apply -f <YAML_FILE>

# 删除资源对象
kubectl delete -f <YAML_FILE>

  4. 查看资源对象的详细信息：

    bash
    # 查看 Pod 详细信息
kubectl describe pod <POD_NAME>

# 查看 Service 详细信息
kubectl describe service <SERVICE_NAME>

# 查看 Deployment 详细信息
kubectl describe deployment <DEPLOYMENT_NAME>

# 查看 ReplicaSet 详细信息
kubectl describe replicaset <REPLICASET_NAME>

  5. 查看 Pod 日志：

    bash
    kubectl logs <POD_NAME>

  6. 进入 Pod 中的容器：

    bash
    kubectl exec -it <POD_NAME> -- /bin/bash

  7. 扩容和缩容应用程序：

    bash
    # 扩容 Deployment 的副本数
kubectl scale --replicas=<REPLICA_COUNT> deployment/<DEPLOYMENT_NAME>

# 缩容 Deployment 的副本数
kubectl scale --replicas=<REPLICA_COUNT> deployment/<DEPLOYMENT_NAME>

  8. 滚动升级应用程序：

    bash
    # 开始滚动升级
kubectl set image deployment/<DEPLOYMENT_NAME> <CONTAINER_NAME>=<NEW_IMAGE>:<TAG>

# 查看滚动升级状态
kubectl rollout status deployment/<DEPLOYMENT_NAME>

# 回滚到先前的版本
kubectl rollout undo deployment/<DEPLOYMENT_NAME>

高级命令 ​

下列包含本地监听、复制文件和 API 代理，各有相应权限与副作用。

  1. 使用 kubectl port-forward 命令将本地端口绑定到 Pod 端口：

    kubectl port-forward <POD_NAME> <LOCAL_PORT>:<REMOTE_PORT>

    该命令会将本地端口 <LOCAL_PORT> 绑定到远程 Pod 的端口 <REMOTE_PORT>。例如，要将本地端口 8080 绑定到名为 my-pod 的 Pod 中的端口 80，可以使用以下命令：

    kubectl port-forward my-pod 8080:80

  2. 使用 kubectl cp 命令在容器和本地文件系统之间复制文件：

    kubectl cp <POD_NAME>:<CONTAINER_PATH> <LOCAL_PATH>
kubectl cp <LOCAL_PATH> <POD_NAME>:<CONTAINER_PATH>

    该命令可以将文件从本地文件系统复制到运行中的容器中，或者将文件从容器中复制到本地文件系统中。例如，要将名为 my-pod 的容器中的 /app/logs 目录复制到本地文件系统中的 /tmp 目录，可以使用以下命令：

    kubectl cp my-pod:/app/logs /tmp

  3. 使用 kubectl top 命令查看节点和 Pod 的 CPU 和内存使用情况：

    # 查看节点的 CPU 和内存使用情况
kubectl top node

# 查看 Pod 的 CPU 和内存使用情况
kubectl top pod

  4. 使用 kubectl proxy 命令在 Kubernetes API 服务器和本地之间建立代理：

    kubectl proxy

    该命令会在本地启动一个代理，将 Kubernetes API 服务器和本地连接起来。通过访问 http://localhost:8001，您可以访问 Kubernetes API，并查看集群状态、部署资源等。
