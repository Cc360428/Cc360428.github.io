PowerShell：发布、排障与恢复练习 ​

脚本发布、编码与恢复 ​

维护PowerShell CSV 汇总前先保存PowerShell 7.4、UTF-8 category/count 输入与对象管道，恢复后以字段校验、错误流、退出码和 Category/Total 对象验收。具体配置见配套示例。

教学版本族：PowerShell 7.4 与 .NET 8 语义；Windows PowerShell 5.1 不获得编码、原生命令传参与模块兼容保证。核对日期2026-10-17，不称为2026最新版。示例未执行，配置与命令需按目标环境验收。

模块与执行策略边界 ​

PowerShell 模块应固定来源与版本并先审阅导出命令，本例依赖内置 Microsoft.PowerShell.Utility/Management。执行策略影响脚本加载体验，不是完整安全边界；不为运行样例建议全局 Bypass 或 Unrestricted。受组织策略约束时改用获准签名/交付流程，本文不更改策略。

输出原子性与恢复 ​

PowerShell 输出恢复要区分内存对象成功和文件提交成功。管道接收方可能在前几个对象后失败，所以不能把“脚本先校验”当作端到端原子提交。需要文件产物时由调用层在受控目录写临时文件、核对退出码后发布，并约定重名覆盖；本例不写文件也不注册任务。

精确清理与编码 ​

PowerShell 清理只涉及用户复制的 CSV 和自行保存的输出。先确认绝对路径，再用 LiteralPath 删除确切文件，不把通配符和递归删除混合。UTF-8无BOM与带BOM、5.1默认输出编码有差异，应在持久化边界显式选编码；课程输入为UTF-8 ASCII子集，源码不自动改写原输入。

练习与参考解答 ​

题目：good.csv被汇总成功，调用者需要保存CSV并再次显示表格；还收到“脚本被组织执行策略阻止”的另一份记录。应在哪里选择编码与格式化，是否应全局改Bypass重试？

参考解答：对汇总对象先用明确UTF-8编码导出，保留原业务字段；显示分支再Format-Table，不把显示指令作为保存数据。组织策略阻止发生在业务校验前，应遵循获准签名或交付流程，不全局改Bypass，也不能把该记录算作负数输入拒绝成功。示例未修改系统，恢复只涉及自行保存的确切产物。

参数、非终止错误与退出码排障 ​

本节沿字段校验、错误流、退出码和 Category/Total 对象定位失败层；先确认PowerShell 7.4、UTF-8 category/count 输入与对象管道，与配套示例逐项对照，再选择最小修复。

属性不存在与格式化 ​

PowerShell 属性不存在先用 Get-Member 看实际对象类型，再核对是否提前 Format-Table 或来自原生文本。不要改列名碰运气；把对象、CSV字符串与格式指令分开。本例严格模式让错误属性更早失败，不把 null 默认为正常数据。

原生命令状态与重定向 ​

PowerShell 原生命令失败要检查退出码和 stderr，$? 只代表最近操作状态；随后执行别的命令可能覆盖观察。本例刻意不用外部程序，避免跨平台参数转义和编码牵扯；日后加入原生命令时应单独定义成功码、参数与输出协议。

脚本加载与数据失败 ​

PowerShell 脚本加载被策略阻止发生在业务校验之前，不能把它计为 CSV 拒绝路径通过。分开记录签名/策略错误、参数绑定错误与输入验证错误。不要执行未经审查的远程脚本绕过限制。

练习与参考解答 ​

题目：Import-Csv读入一行category=alpha、count=-1，另一次管道先Format-Table后尝试访问Category，得到属性不存在。前者为何返回2，后者为何不能靠加一列空Category“修复”？

参考解答：负数字符串不符合示例允许的十进制非负整数字段，属于已定义输入拒绝，退出2且不输出汇总。第二个问题是数据类型已被格式化转换，应回到格式化之前的业务对象链检查Get-Member，而非伪造空属性掩盖错误；补空列会损失真实分类。两个故障分别在字段校验与对象链路，不能混为CSV文件损坏。

任务显示成功却缺少数据的复盘 ​

以下演练将PowerShell CSV 汇总的变更、失败证据和恢复验收串起来；先熟悉配套示例中的PowerShell 7.4、UTF-8 category/count 输入与对象管道。演练未执行。

故障场景与影响 ​

任务记录为成功，但汇总文件少了一部分数据，日志中出现非终止错误。

先记录首次异常时间、受影响对象和最近变更，区分个别对象失败与整条管理链路异常。以下是排查演练，不是已发生事故的实测记录。

按证据定位原因 ​

  1. 核对执行的是 PowerShell 7 还是 Windows PowerShell 5.1，并保存任务参数与输入编码。
  2. 检查每个输入读取与转换阶段的 ErrorRecord；确认需要中止的 cmdlet 错误是否按约定转为终止错误并被处理。
  3. 对原生程序另查其退出码；检查 Write-Output 是否把调试文字混入了业务对象流。

恢复步骤与验收 ​

使关键失败中止产物提交，通过独立诊断流保留原因；显式处理原生程序的失败状态，不将部分结果覆盖正式汇总。

验收：正常输入仅输出约定对象；缺失文件、非法 CSV 与原生命令失败都返回约定状态。确认任务退出码、输出条数与文件内容一致。

将触发条件、直接原因、修复动作、恢复证据和后续检查写入同一份复盘，明确每项后续工作的负责人。机制参考：官方说明。

对象链路自检 ​

解释从 CSV 字节到字符串字段、校验后的 long、分组对象、格式化显示四个阶段。每个阶段的数据类型和错误不同，显示“5”并不能证明原值是整数5。没有业务校验的类型转换无法承担输入契约。

独立边界练习 ​

不运行脚本，推演空CSV、多余字段、负数、单行和1001行输入。再写出将结果导出CSV时应该放在哪个阶段，以及为什么记录错误信息不能通过 Write-Output 混入结果。

参考解答与范围 ​

空表、多余字段、负数和超限行数均拒绝；一行仍是数组并可聚合；在汇总对象阶段导出，格式化只放显示末端。错误用错误流并明确非零退出。本课不覆盖远程管理、DSC、云SDK；Windows系统对象与跨平台自动化分别走独立入口。
