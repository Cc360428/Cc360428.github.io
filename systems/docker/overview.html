1. 阅读说明 ​

本知识库同时覆盖“为什么”“怎么做”和“出问题怎么办”。所有命令默认在 Linux Shell 中执行；示例名称、端口、路径和镜像仓库地址应按实际环境替换。

文档中的提示分为三类：

  • 提示：推荐做法或容易忽略的行为。
  • 警告：可能中断服务、暴露端口或改变数据。
  • 危险：可能删除镜像、容器、卷或宿主机文件；执行前必须确认目标并完成备份。

Docker 命令通常要求访问 Docker daemon。加入 docker 用户组等价于授予接近宿主机 root 的权限，不应把它当作普通的免 sudo 便利设置。生产环境优先使用最小授权、Rootless 模式或受控的远程上下文。

4. 先记住的五个原则 ​

  1. 镜像不可变，数据外置。 应用版本进入镜像，业务数据进入卷或外部服务。
  2. 按摘要部署。 标签可移动；生产发布记录应保留镜像 digest。
  3. 容器不是虚拟机。 一个容器通常承载一个主要职责，并通过前台主进程维持生命周期。
  4. 默认最小权限。 非 root 用户、只读根文件系统、删除多余 capabilities，不挂载 Docker socket。
  5. 删除前先盘点。 先执行 docker system df -v、检查标签和卷，再使用 prune 类命令。
