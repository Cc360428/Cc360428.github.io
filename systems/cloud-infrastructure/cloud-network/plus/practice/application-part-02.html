# 云网络双向路径审阅工作表

示例未执行，不含云CLI、网络服务或模拟器，无需安装依赖。topology.json是完整教学拓扑，paths.json是逐跳正反向审阅与失败预期；它们是自定义工作表，不可提交给AWS API。私有地址需要读者映射到自己的隔离VPC；192.0.2.10和example.invalid是保留示例，必须替换，不能假称公网可达。

读者自跑方式是离线阅读JSON并画出双方五元组，无命令前置。app的10.40.1.10:49152连接db的10.40.2.10:5432；核对双方子网关联路由表，10.40.0.0/16 local匹配；app-sg出站与db-sg入站允许5432，安全组对已建立返回流量有状态。NACL自定义规则必须另放行app出站5432/db入站5432，以及db出站49152/app入站49152；示例以1024–65535覆盖课堂临时端口，实际须结合客户端OS端口范围缩窄。所有未匹配项隐式拒绝，规则号升序首匹配。

成功预期仅为静态规则允许此路径，不证明接口已关联、OS防火墙允许或数据库正在监听。失败推演：移除app的入站临时端口规则，返回包被NACL拒绝；把DNS答案写成旧私网地址，安全组再宽也不能修复目标错误；公网客户端没有公网地址/互联网路由/来源授权，不能访问DB。

DNS给出私有名称db.lab.example.invalid、10.40.2.10、TTL60；这只是工作表条目，尚未创建任何zone。读者应逐层核对解析器、zone关联、TTL和真实返回答案；VPC AmazonProvidedDNS有专门的过滤边界，NACL不能笼统当作DNS过滤器。

恢复清理：保留变更前路由/关联/规则号，按路径定位最小回退，不通过0.0.0.0/0入站放通排错。此工作表没有真实网络需清理；删除自行创建的副本即可。真实环境要先解除依赖再删除专属路由、接口、网关，防止误删共享VPC资源。

## 完整资源配置



network.yaml完整声明VPC、两个子网、专属路由表与关联、两组安全组、NACL及关联/四条规则、私有zone和A记录。路由表自动具有VPC local路由，不添加公网默认路由、IGW、NAT或计算实例。模板app安全组出站使用10.40.2.0/24目的网段，JSON工作表则用db-sg目标引用表达更窄的身份设计；两者是明确的替代形式，真实部署前应选择符合依赖关系的规则。db组只放行app组入站，显式回环限定出站规则用于防止自动放行全部出站，已建立回流仍依安全组状态；NACL另显式放行回包。

示例example.invalid私有名称与10.40网段必须由读者映射到自有隔离环境，确保地址不重叠。A记录中的10.40.2.10仅预留数据库位置，模板没有数据库或监听程序，所以部署网络后仍不可据此判断应用可达。成功预期仅是网络对象与关联建立；DNS权限/配额/冲突或错误区域会导致失败。日后读者用自有change set流程审阅后执行，本轮未调用；清理先删除专用记录/zone与接口依赖，再删除专用stack，禁止操作共享VPC。

[安全组属性与默认出站规则](https://docs.aws.amazon.com/AWSCloudFormation/latest/TemplateReference/aws-resource-ec2-securitygroup.html)

练习：部署network.yaml后访问db域名就能连数据库吗？

参考解答
