云资源：基础对象与机制 ​

账户、区域、实例与资源清单 ​

云主机管理首先是资源关系管理：实例、磁盘、网卡、地址、角色和备份各有生命周期。操作前确认账户、区域与资源 ID，再判断停止、重建或终止分别影响哪些对象。

资源身份与清单 ​

云资源清单先记录账户、区域、实例ID、所有者、环境、用途和依赖，再做任何启停判断。显示名称可以重复，实例ID也必须结合区域与账户解释；不要仅凭一个“test”标签删除资源。云主机是计算资源，云盘、网卡、地址、快照、IAM角色是关联对象，生命周期不总一致。课堂inventory是保存文件，不证明云端当前状态。

只读与变更操作入口 ​

云资源操作入口要区分Describe/Get只读查询和Start/Stop/Terminate变更。AWS CLI或其他云SDK即使叫dry-run也可能访问账户。读者以后须先确认身份、区域、分页、过滤和资源ID，再审核变更；命令返回请求成功不等于实例已达到目标状态。示例只读本地JSON并生成审阅结果，不把它称为真实云操作。

区域、可用区和配额 ​

云资源区域边界影响数据位置、服务端点与费用，可用区决定网络与磁盘挂载限制。配额、镜像架构、实例规格、区域容量与许可都可能阻止创建；一个区域的成功不保证另一地区可用。AWS与阿里云停止计费及保留公网地址的条件不同，必须查所选计费模式，不能把“停止”统一解释为完全免费或所有地址不变。

本篇练习与参考解答 ​

练习：一台实例名为test就能安全删除吗？

参考解答

不能。名称可重复，需核对账户、区域、ID、owner、依赖与备份，且静态清单可能已过期。

IAM、实例状态与磁盘生命周期 ​

先明确账户、区域、实例/卷身份与 IAM 角色，再对照配套示例理解停止/终止影响、卷保留和备份可恢复性。

核对日期2026-10-17；适用范围：以AWS EC2 2016-11-15 API模型与IAM概念为例，并对照阿里云ECS中文生命周期说明；云控制台与服务特性按2026-10-17核对，不声称跨云接口等价。示例未执行；真实环境仍需验证产品配置、权限、连通与恢复结果。先读起点理解前置，再按章节完成推演。

IAM身份与最小权限 ​

云资源IAM授权要分清调用者身份、实例角色和角色信任关系。EC2实例配置文件承载角色，应用通过短期凭据访问被允许的接口，避免把静态访问密钥写在镜像或启动脚本中。只读Describe策略只允许列举，不能赋予停止或删除能力；某些Describe动作需Resource=*并不代表所有动作都应该通配。显式拒绝、组织策略与权限边界可能让Allow仍失败。

停止、重启和终止 ​

云资源生命周期中reboot重启系统，stop停止计算，terminate终止实例，三者对数据和计费影响不同。EC2 EBS支持实例停止后保留卷，但实例存储数据与公网地址有各自条件；root卷DeleteOnTermination决定终止时是否删除。停机并不等于备份，终止不能用start撤回。阿里云停止模式还与VPC、按量及节省停机选项有关，不能照搬EC2结论。

持久卷和快照一致性 ​

云资源快照通常是某时刻块设备状态，不自动保证应用事务一致。应让应用刷盘或使用合适的应用一致性备份方案，并记录恢复点、加密密钥和恢复依赖。多卷数据库要协调多个卷的时间关系；快照成功不代表恢复演练通过。卷保留策略、删除保护与跨区域复制也不能替代明确的RPO/RTO，复制错误数据仍然是错误数据。

本篇练习与参考解答 ​

练习：Describe策略和实例角色信任策略是否同一份权限？

参考解答

不是。信任关系决定谁能承担角色，权限策略决定角色能做什么，实例配置文件再将角色关联到EC2。
