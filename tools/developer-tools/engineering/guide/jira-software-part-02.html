6. 可直接复制的 JQL ​

以下示例默认使用项目键 PAY。复制后请替换项目键、状态、版本、组件和自定义字段名称。

6.1 我的未完成任务 ​

text
project = PAY
AND assignee = currentUser()
AND statusCategory != Done
ORDER BY priority DESC, updated DESC

适合保存为个人每日入口。

6.2 当前 Sprint 未完成任务 ​

text
project = PAY
AND sprint in openSprints()
AND statusCategory != Done
ORDER BY rank ASC

适合站会和 Sprint 执行检查。

6.3 Backlog 中尚未估点的任务 ​

text
project = PAY
AND sprint is EMPTY
AND statusCategory != Done
AND "Story Points" is EMPTY
ORDER BY rank ASC

"Story Points" 是常见自定义字段，团队实例中的名称可能不同。

6.4 最近 7 天新建的 Bug ​

text
project = PAY
AND issuetype = Bug
AND created >= -7d
ORDER BY priority DESC, created DESC

6.5 高优先级且未完成 ​

text
project = PAY
AND priority in (Highest, High)
AND statusCategory != Done
ORDER BY priority DESC, created ASC

按创建时间升序可以优先暴露长期未处理的问题。

6.6 已逾期且未解决 ​

text
project = PAY
AND due < startOfDay()
AND resolution is EMPTY
ORDER BY due ASC

6.7 无负责人任务 ​

text
project = PAY
AND assignee is EMPTY
AND statusCategory != Done
ORDER BY priority DESC, created ASC

6.8 本周发生过状态变化 ​

text
project = PAY
AND status CHANGED AFTER startOfWeek()
ORDER BY updated DESC

6.9 进入完成状态后又被重新打开 ​

状态名需要替换为团队实际工作流状态：

text
project = PAY
AND status CHANGED FROM Done
AND statusCategory != Done
ORDER BY updated DESC

6.10 指定版本尚未完成的任务 ​

text
project = PAY
AND fixVersion = "2026.08"
AND statusCategory != Done
ORDER BY priority DESC, rank ASC

6.11 按组件和标签筛选 ​

text
project = PAY
AND component = backend
AND labels in (tech-debt, performance)
AND statusCategory != Done
ORDER BY priority DESC

6.12 搜索标题或描述中的关键词 ​

text
project = PAY
AND text ~ "timeout"
ORDER BY updated DESC

只搜索标题时：

text
project = PAY
AND summary ~ "timeout"
ORDER BY created DESC

6.13 找出近期没有更新的进行中任务 ​

text
project = PAY
AND statusCategory = "In Progress"
AND updated < -3d
ORDER BY updated ASC

适合识别可能阻塞或忘记更新的任务。

6.14 我创建但尚未分配的任务 ​

text
project = PAY
AND reporter = currentUser()
AND assignee is EMPTY
AND statusCategory != Done
ORDER BY created DESC

7.1 过滤器命名建议 ​

采用统一命名可以减少重复建设：

text
[团队/项目] 用途 - 范围

例如：

  • [PAY] 当前 Sprint - 未完成
  • [PAY] 发布检查 - 2026.08
  • [个人] 我的高优先级任务

7.2 共享过滤器前检查 ​

  • 查询不要依赖只有创建者可见的项目或字段。
  • 需要“每个人看到自己的任务”时使用 currentUser()。
  • 确认共享范围，避免向所有登录用户开放敏感项目结果。
  • 修改被看板或仪表盘引用的过滤器前，先确认影响范围。

8. 看板快速筛选建议 ​

快速筛选适合在不改变看板基础范围的情况下，临时聚焦一类任务。

名称JQL
只看我的assignee = currentUser()
高优先级priority in (Highest, High)
Bugissuetype = Bug
无负责人assignee is EMPTY
长期未更新updated < -3d AND statusCategory != Done
技术债labels = tech-debt

基础看板过滤器负责定义“哪些任务属于这个看板”，快速筛选只负责临时聚焦。不要把复杂的权限和项目边界都放进快速筛选。

9. 常见误区与修正 ​

9.1 != 不会自动包含空值 ​

下面的查询不会返回未分配任务：

text
assignee != currentUser()

需要显式包含空值：

text
assignee != currentUser() OR assignee is EMPTY

组合其他条件时加括号：

text
project = PAY
AND (assignee != currentUser() OR assignee is EMPTY)

9.2 resolution = Unresolved 不够稳妥 ​

查找未解决任务通常使用：

text
resolution is EMPTY

工作流在关闭或重新打开任务时，应同步正确设置或清空 Resolution，否则搜索结果和报表会失真。

9.3 显示名、字段名和状态名可能变化 ​

  • 带空格的值或字段名使用双引号，例如 "Story Points"。
  • 自定义字段重名时，使用 Jira 自动补全确认字段。
  • 跨项目查询尽量使用 statusCategory，减少具体状态名差异。
  • 用户字段优先选择自动补全结果，不要手工猜账号标识。

9.4 ORDER BY 不是筛选条件 ​

text
ORDER BY priority DESC, updated DESC

这只会改变展示顺序，不会减少结果。查询慢时，应先缩小项目、时间、Sprint 或版本范围。

9.5 文本搜索不是精确数据库匹配 ​

~ 使用 Jira 的文本搜索规则，分词、特殊字符和模糊匹配行为可能与直觉不同。搜索任务编号、版本、组件等结构化信息时，应优先使用对应字段。

10. JQL 排查方法 ​

查询报错或结果不符合预期时，按以下顺序处理：

查看图表代码

实用排查步骤：

  1. 只保留 project = PAY，确认基础范围。
  2. 每次只增加一个条件，观察结果数量。
  3. 使用编辑器自动补全选择字段、函数和值。
  4. 临时移除 OR 和历史查询，先验证普通条件。
  5. 用一条已知任务反向核对每个字段的真实值。
  6. 确认自己拥有浏览对应项目和任务的权限。

11. 团队落地建议 ​

每日 ​

  • 更新自己正在处理任务的状态和剩余信息。
  • 处理 @ 提及、阻塞和高优先级任务。
  • 用“我的未完成任务”过滤器作为个人工作入口。

每周 ​

  • 清理无负责人、长期未更新和已逾期任务。
  • 检查 Backlog 顶部任务是否具备进入 Sprint 的条件。
  • 关闭重复、失效或已经通过其他方式完成的任务。

每个 Sprint ​

  • 规划前：确认范围、估点、依赖和验收条件。
  • 执行中：看板状态与真实进度保持一致。
  • 结束前：检查未完成、重新打开和版本遗漏任务。
  • 复盘时：结合过滤器和报表讨论流程问题，不只讨论个人产出。

12. JQL 速查卡 ​

text
# 当前用户
assignee = currentUser()

# 未完成
statusCategory != Done

# 当前 Sprint
sprint in openSprints()

# 最近 7 天
created >= -7d

# 今天更新
updated >= startOfDay()

# 空值
assignee is EMPTY

# 多个值
priority in (Highest, High)

# 文本搜索
summary ~ "timeout"

# 历史变化
status CHANGED AFTER -7d

# 排序
ORDER BY priority DESC, updated DESC

术语变化

Atlassian 正在将部分界面术语从 “issue” 调整为 “work item”、从 “project” 调整为 “space”。现有 JQL 查询不会因此失效；如果新术语对应的字段暂时不可用，可继续使用原有字段名。
