MongoDB：连接诊断、备份恢复与自检 ​

连接诊断与备份恢复边界 ​

适用 MongoDB 8.0 版本族；mongosh、PyMongo、Database Tools 各有独立发布周期，应分别核对兼容性。核对日期 2026-10-17。本轮示例和维护命令全部未执行，没有连接真实或模拟服务。

连接、认证与授权诊断 ​

MongoDB ServerSelectionTimeoutError 是在期限内无法选择合适服务器，不仅可能是端口不通，也可能是副本集发现的成员地址不可达、replicaSet 名不匹配或 TLS 条件不符。先核对脱敏 URI 的主机、拓扑、DNS、证书与连接时限，再查看有权限的服务诊断。不要为了消除错误就跳过证书验证。

AuthenticationFailed 与 Unauthorized 方向不同：前者先查凭据、机制及 authSource，后者先查角色是否允许当前库和操作。能连接不代表有建索引权限，show dbs 的显示也受权限影响。旧认证文中 use 仅切换上下文，不能把切库当成已经建好数据库。官方连接资料见连接 MongoDB。

explain 与容量调查 ​

MongoDB explain 应记录过滤器、排序、投影、索引和数据分布，再看 examined 与 returned 的比例；COLLSCAN 不自动等于错误，小集合或低选择率可能合理。新增索引会占用磁盘和缓存，也增加写放大。游标批次、查询超时和连接池上限都需要与应用并发一起考虑，单调加大池不等于提高吞吐。

版本冲突返回 3 是业务并发控制信号，应刷新状态后由业务决定是否重试。写关注超时则需要检查是否已经写入；其结果不确定性不能被一般“失败重试”策略掩盖。此类运行诊断本轮未测。

mongodump 的一致性边界 ​

MongoDB mongodump 是逻辑备份工具，不是导出 JSON；mongorestore 读取对应 BSON 与元数据。活动写入期间，普通 dump 不应被理解成所有集合严格同一时刻的快照。副本集全量转储配合 --oplog 有特定条件和限制；不能把选择单库的 --db 与 --oplog 任意组合，分片集群也不能直接套副本集方法。官方 mongodump

下面只供读者评审停写维护窗口内单库逻辑备份方案，不在本轮执行。由已有授权连接串环境变量提供目标，命令示意在 PowerShell 中使用 $env:MONGODB_URI，Linux 则用 "$MONGODB_URI"。凭据参数可能在进程信息中出现，应按环境选用官方受支持的安全凭据配置。

powershell
mongodump --uri "$env:MONGODB_URI" --db theory_tasks --archive tasks.archive --gzip
mongorestore --uri "$env:MONGODB_URI" --archive tasks.archive --gzip --nsInclude 'theory_tasks.*' --nsFrom 'theory_tasks.*' --nsTo 'theory_tasks_restore.*' --stopOnError

前提是业务停写窗口、目标命名空间不存在且操作者有相应权限，恢复命令会写入新库；不能把一个已有同名库当作无害目标。不使用 --drop，仍应预先确认目标为空；恢复中途出错可能留下部分内容。生产大规模恢复、时间点恢复和分片备份需专门方案，不能由此单库例子背书。

恢复校验与副本区别 ​

MongoDB 恢复校验应比较文档数、确定排序后的业务字段、索引定义、验证器与应用查询，再记录工具版本和错误退出状态。成功退出码只是一步，不证明业务约束或账户恢复完成。mongodump 不自动包含所有集群配置、外部密钥、应用附件和完整权限方案；备份清单需单独列出这些资产。官方 mongorestore

副本集提高可用性，但误删除也会复制，不能代替独立备份。先定义可接受数据丢失量 RPO 与恢复用时 RTO，再决定周期、异地保存和恢复演练。练习：三个节点能否防止一次合法但错误的 deleteMany？答案：不能，复制会忠实传播逻辑错误，需要独立恢复点和业务审计。

复习与一致性阶段实践 ​

前置是 BSON、模型、索引、单文档更新和维护边界。适用 MongoDB 8.0 版本族及 PyMongo 4.x，核对 2026-10-17；全部实践未执行。

先独立作答 ​

MongoDB 复习题要求明确原子性、一致性和备份三个不同保证。请回答：字符串日期是否自动是 BSON Date；内嵌无限评论是否合理；updateMany 是否整批原子；standalone 能否执行多文档事务；majority 是否等于每个 secondary 立即可见；副本集是否就是备份。

先用任务 CLI 的字段和拓扑解释，再查参考答案。不要只写“MongoDB 支持事务”这种缺乏前提的句子；也不要沿用旧文“不支持跨文档 ACID”的过时概括。旧文章保留 URL 是历史兼容，不代表每个历史结论都适用于当前教学版本。

阶段综合实践 ​

MongoDB 阶段实践是设计“任务完成与审计记录同时成功”的方案。先给出独立文档版本条件，说明它能保护什么；再把审计拆为第二个集合，写出为何两次普通更新不够，以及采用副本集事务时需要会话、提交和重试。为外部邮件副作用画出提交后处理路径，解释重复投递如何幂等。

预期交付是状态图、过滤器、失败分类与恢复检查表，不是运行截图。本轮没有执行服务或事务；完整 CLI 只实现单文档状态转移，不冒称已经实现这个扩展题。参考事务官方说明。

参考解答与判断依据 ​

MongoDB 事务答案首先要求副本集或分片集群拓扑；单文档版本条件保证一条文档的一次匹配更新，不能自动把另一集合也纳入。回调重试可能重复运行代码，邮件不能直接当成数据库事务的一部分。可将待发送事件与业务修改同事务保存，再由消费者按事件 ID 去重处理，实际交付语义需要另行验证。

字符串日期需要显式转为日期类型；无界内嵌要考虑文档上限与热点。updateMany 每条文档原子，整批不等同事务。majority 确认与读路由是不同维度，secondary 仍可能延迟；复制也会传播误删，需独立备份。上述回答依据官方原子性与一致性。

自检与后续范围 ​

通过本课应能为给定查询设计文档边界、说明索引顺序、区分版本冲突与结果不确定，以及制定可验证备份清单。分片键选择、跨区故障切换、PITR、Change Streams、加密和生产容量需要专门课程与运行证据。本轮静态语法解析不能代表这些能力运行通过。
