MinIO 传输校验、重试与生命周期边界 ​

字节、哈希与 ETag ​

前置：能运行对象备份。校验至少分三层：HTTP 请求成功、字节数匹配、内容校验匹配。本课程先用 Buffer.equals 逐字节比较，再计算 SHA-256 存入 manifest；这能发现文本编码、截断或内容改变。相同长度不表示相同内容，200 响应也不表示用户拿到了期望版本。

ETag 是服务端返回的实体标识，不能普遍当作 MD5。分段上传、加密和实现细节会改变它的结构与意义。即便某个小对象 ETag 恰好等于 MD5，也不能把这个观察外推到所有对象。跨系统传输的内容完整性应明确采用双方认可的校验字段或自行保存 SHA-256，同时保留对象版本与大小。

powershell
node --test examples/minio/app.test.mjs

单测将 hello 与 hellO 比较，预期抛 byte mismatch；相同字节返回 64 字符 SHA-256。真实验收包含 UTF-8、换行与非 ASCII 字节，防止只用纯英文小字符串遗漏编码问题。校验哈希不要作为泄露敏感文件特征的公开索引。

流式与分段上传 ​

SDK putObject 可处理流与分段上传，上传成功后才有完整可见对象；中断的 multipart 可能留下未完成分段并占空间。大文件应使用已知长度的流、合适分段尺寸和有界并发，不能把本项目 Buffer 收集器用于无限输入。下载需消费/关闭流，遗漏会占用连接。

网络超时存在“服务端已提交，客户端没收到响应”的歧义。对同一 key 重试可能覆盖对象或在版本桶中新增版本，不能把幂等的最终可见内容理解为“没有额外历史版本”。业务要保存稳定对象 key、内容哈希、上传任务状态和返回 versionId，必要时查询确认，有限重试并退避。

本包没有验证多 GB 流、multipart 中途失败、并发上限或断点续传；历史记录只涉及小对象真实上传下载和应用失败退出，本轮不复测。演示 HTTP 本机通信不提供链路机密性，跨网络使用 TLS 并校验证书，不能用关闭证书校验来修复配置错误。

生命周期与历史保留 ​

生命周期规则由服务端后台异步评估，不是“配置后立刻删除”的同步命令。版本桶应分别设计当前版本过期、noncurrent version expiration、删除标记与未完成 multipart 清理。仅让当前对象过期可能产生删除标记，旧版本仍占空间；永久删除非当前版本会破坏对应恢复能力。

配置前先明确恢复窗口、合规保留与对象锁约束，再对有限前缀试验。规则有过滤条件、天数/日期和状态，不能把一个服务商的 XML 示例未经核对当作所有 S3 实现通用参数。备份保留与源生命周期要独立设计，避免源和备份同时被删除。

本次没有等待按天执行的生命周期任务，因此不声称清理时间或容量已验收。运维应观察规则、后台扫描状态、当前/历史版本数量和存储使用，再以实际对象的变化验证。删除标记为零字节也仍有元数据成本。

练习与参考解法 ​

题目：上传一个文件得到带连字符的 ETag，能否以 ETag 作为整个文件 MD5？设置“当前对象 7 天过期”能否保证 7 天后历史数据全部消失？

提示：先判断 ETag 是否承诺整个文件的 MD5，再分别检查当前版本和非当前版本的生命周期。

参考答案与边界

都不能。multipart 常有组合形式 ETag，应计算 SHA-256 或使用明确校验协议；版本桶当前对象过期不等于永久清理全部历史，且执行是异步的。先对版本、删除标记与非当前版本建立清单，再按保留要求设计规则。本课程 SHA-256 manifest 只覆盖当前可见对象。
