MinIO：备份恢复、签名排障与自检 ​

MinIO 独立恢复与 S3 故障诊断 ​

本轮为理论笔记与静态审读，示例、安装命令和验收器均未执行。下文命令用于解释步骤，预期结果不代表本轮实测；“历史验收”仅指此前批次记录。阅读和书面练习不需要启动服务。

恢复到独立目标 ​

前置：备份 manifest 与对象文件已生成并保存在源卷之外。恢复不是把运行中的 /data 目录随意拷贝到另一实例，而是通过已定义的 S3 对象合同上传到独立目标。项目验收先检查目标桶不存在，再恢复一份当前对象，下载并逐字节/SHA-256 验证。

本机端口固定 23000，所以先停止源 showdocs-m4b-minio-main，新容器 showdocs-m4b-minio-restore 使用独立 showdocs-m4b-minio-restore-data 卷并占用释放的端口；源卷保留不动。验证完成停止目标，再重启源。完整命令与断言见真实验收器，初次运行成功后结果包含桶名、hash 与恢复数量。

恢复结果只包括备份时当前可见对象，不含原始 versionId、历史、删除标记、权限、生命周期和全部元数据。原版本化桶被恢复成普通新桶也不会自动继承版本配置。业务应把桶配置单独纳入备份计划，并按目的检验权限与应用读取；不能用“备份文件存在”代替恢复成功。

连接、权限与签名排错 ​

powershell
docker ps --filter name=showdocs-m4b-minio
docker logs --tail 40 showdocs-m4b-minio-main
node examples/minio/app.mjs backup 不存在的桶 examples/minio/error-output

连接拒绝先检查容器、端口与 endpoint；S3 API 走 9000/主机23000，不是控制台端口。NoSuchBucket 指向桶名或目标实例错误，NoSuchKey 指向当前不可见键或删除标记。AccessDenied 是权限问题，SignatureDoesNotMatch 是签名条件不一致；两者都可能返回 403，但处理不同。RequestTimeTooSkewed 等时间错误要检查时钟同步。

日志保留错误码、请求 ID、对象键的脱敏形式与时间，隐藏 secret、Authorization 和完整预签名 URL。根凭据能连接不代表应用最小权限正确；用实际受限身份验证必要动作与拒绝动作。本课验收的是私有桶匿名拒绝和签名篡改拒绝，没有把它扩大为完整 IAM 策略矩阵。

停止失败与持久化 ​

powershell
docker stop showdocs-m4b-minio-main
node examples/minio/app.mjs backup course-实际编号 examples/minio/stopped-output
docker start showdocs-m4b-minio-main

服务停止后 CLI 应非零且报告连接失败。若返回空 manifest 还退出成功，就是把不可达误当空桶的程序错误。重启源后读回数据证明同一个独立源卷持久化有效；这只是单节点重启保留，不证明 HA、磁盘故障容错或生产恢复时间。

单实例单盘实验不提供生产高可用；生产还需维护状态评估、故障域、擦除编码/部署拓扑、容量、水位、证书与密钥管理。不要把历史社区部署教程的节点数或商业 AIStor 功能直接套到本源码版本，先核对所选实现和支持边界。

资源清单与练习 ​

本包容器：showdocs-m4b-minio-main、showdocs-m4b-minio-restore。卷：showdocs-m4b-minio-data、showdocs-m4b-minio-restore-data。镜像 showdocs-m4b-minio:2025-10-15 为本机构建产物；构建缓存和基础 Go/Python 镜像可能被其他任务复用，不应全局清理。先 inspect 核对后仅移除上述明确资源，不使用 volume/system prune。

练习：恢复后源对象还在，目标版本 ID 不同，是否说明恢复失败？提示：先写明恢复合同要求保持的字段，检查 versionId 是否在其中。

参考答案与边界

没有；本合同恢复内容且不改源，versionId 由目标生成。判断以字节/hash、对象集合及约定元数据为准。如果要求恢复历史版本和权限，则当前备份合同不足，需扩展而不是把成功日志改成更大的承诺。

未完成 MinIO 草稿的配置合同 ​

MinIO 容器启动草稿的 /home/data 与 /Users 挂载是否相同？ 旧 MinIO 草稿明确标注第一条命令“没用”，第二条只改地址，没有成功启动、S3 写读或持久化验收，因此撤回其部署步骤。它把主机目录、容器挂载目标与 server 参数混用，重复 minio/minio server，并将 docker=admin 写作环境变量；不能从这些片段推定任何认证或数据目录配置成立。旧 MINIO_ACCESS_KEY/MINIO_SECRET_KEY 也不作为本课所选源码版本的配置依据。

容器部署必须分别列明主机端口到 API 端口的映射、容器内实际数据目录、卷来源、运行用户及凭据读取方式。宿主机创建 /home/data 与实际挂载 /Users/... 是两个不同对象；给其中一个目录 chmod 777 不能修复另一路径，更会扩大访问。数据卷只证明打算持久化，不证明已有备份或能独立恢复。

有用的验收目标是：客户端连接的是 S3 API 而非控制台，受限身份能做必要桶/对象动作，拒绝操作确实失败，重启后保留约定数据，独立恢复逐对象核对内容。当前课程提供固定源码与独立卷的学习合同，仍须遵循其维护与版本边界；本次历史清理没有构建镜像、编译程序或重复运行旧/新示例。

MinIO 综合练习与对象存储自检 ​

本轮为理论笔记与静态审读，示例、安装命令和验收器均未执行。下文命令用于解释步骤，预期结果不代表本轮实测；“历史验收”仅指此前批次记录。阅读和书面练习不需要启动服务。

版本与删除练习 ​

前置：读懂完整应用的接口和桶、对象键、versionId。书面目标：推演新建版本化桶、对同一 key 上传 v1/v2、保存各次 versionId、再不带版本删除的状态变化。预测普通 GET、指定 v1 GET、普通列举、带版本列举的结果，先写出预测，再与源码和参考答案核对；不执行命令。

提示：分别预测默认 GET、指定版本 GET、当前列举和版本列举。

参考答案与边界

普通 GET 为 NoSuchKey；指定 v1 能读旧内容；普通列举不显示当前删除标记键；带版本列举可看到删除标记和旧版本。再显式删除 v1，v1 将不可恢复，不能指望删除标记撤销永久删除。版本控制保护部分误覆盖/误删除场景，但持有删除版本权限的身份仍可永久移除历史；版本控制不能代替独立备份。

签名与内容练习 ​

目标：生成 60 秒 GET URL，下载并校验；复制 URL 后改变签名参数，比较错误码。再匿名访问私有对象，解释为什么同样 403 的两种请求原因不同。不要把完整 URL 写入验收记录。

提示：把 HTTP 状态码与 S3 错误码分开记录，核对签名条件。

参考答案与边界

合法签名在有效条件内返回 200/原字节；签名篡改返回 SignatureDoesNotMatch；匿名无授权返回 AccessDenied 类拒绝。状态码只说明大类，S3 错误码帮助定位。到期行为需要另设计时钟和等待测试，历史批次只记录有效、篡改和匿名三项实测，本轮未重跑。ETag 不是通用 MD5，校验内容使用 SHA-256 并保存长度。

损坏与恢复练习 ​

目标：备份当前对象，改动本地对象一个字节而保留原 manifest，执行恢复，应在上传该对象前失败。修复后停止源，在新卷目标恢复，验证相同 hash；随后停目标重启源，确认源内容仍在。

提示：比较原 manifest 与损坏数据的哈希，说明失败前是否可能已有目标副作用。

参考答案与边界

SHA-256 不一致抛 backup checksum mismatch；程序退出 1。恢复成功意味着该合同中每个当前对象的内容正确，不表示恢复全部版本/策略/元数据。如果攻击者能同时修改 manifest 和数据，需签名/认证清单或可信离线副本；普通哈希不能认证来源。

“上传该对象前失败”不代表目标完全没变化：restore 先检查或创建桶，再逐对象校验并上传。首个对象损坏时可能已建桶；后续对象损坏时，前面的对象可能已写入。应按 manifest 核对已完成部分，不能把非零退出解释为跨对象回滚。

本地映射还要测试 ../outside、C:/outside、反斜杠及大小写不同键。程序拒绝危险输入，磁盘文件由键哈希命名，避免直接映射远端路径。把可信备份根目录交给恶意本机用户仍不安全，这不是多租户文件沙箱。

完成标准与后续范围 ​

应能独立解释：桶/前缀、当前对象/历史版本、删除标记/永久删除、预签名/公开权限、SHA-256/ETag、生命周期异步执行/立即删除、当前对象备份/完整站点灾备。能据源码解释正常与拒绝响应、独立恢复的检查项和服务停止时非零退出的预期；本轮不以运行作为完成条件。

本批没有验证生产 HA、持续维护保证、大对象 multipart 故障、生命周期按天清理、TLS/身份策略全矩阵或历史版本完整迁移。尤其社区仓库已归档与 source-only 的事实会影响真实部署选型；课程价值是明确可复跑的 S3 机制实验，不是替历史社区版作生产推荐。
