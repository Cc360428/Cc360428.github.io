MinIO：桶、对象版本与短期授权 ​

固定源码实验与 S3 桶对象 ​

本轮为理论笔记与静态审读，示例、安装命令和验收器均未执行。下文命令用于解释步骤，预期结果不代表本轮实测；“历史验收”仅指此前批次记录。阅读和书面练习不需要启动服务。

版本、分发与运行边界 ​

MinIO 提供 S3 兼容对象接口。桶是命名和策略边界，对象用 key 标识，数据经 HTTP API 上传读取。本课程目标是学会 S3 客户端集成与备份恢复，不把对象存储当作共享 POSIX 文件系统。前置知识为终端、Node、文件路径与 HTTP 状态码。

截至核对日期 2026-10-17，官方 minio/minio 社区仓库已在 2026-04-25 归档；README 声明 source-only，不再提供社区预编译二进制。社区历史文档、商业 AIStor 文档与当前产品不能混作相同维护承诺。本课选官方固定源码发行 RELEASE.2025-10-15T17-29-55Z，对应模块 v0.0.0-20251015172955-9e49d5e7a648，包含该发行说明中的安全修复。它是历史学习基线，不是 latest，也不是默认生产选型或持续安全维护保证。生产决策必须另评估维护、安全更新、许可和支持。

直接拉取官方历史镜像在本次环境中失败（quay 返回 401，DockerHub 仓库不可访问），因此按官方 source-only 路径构建。编译器 Go 1.24.13、CGO_ENABLED=0、Linux amd64；运行时基于 Python slim 只是复用已存在基础镜像，示例不调用 Python。Dockerfile 固定两个基础镜像 digest：

FROM golang:1.24.13-bookworm@sha256:1a6d4452c65dea36aac2e2d606b01b4a029ec90cc1ae53890540ce6173ea77ac AS build
ENV CGO_ENABLED=0
RUN go install -v github.com/minio/minio@RELEASE.2025-10-15T17-29-55Z
FROM python:3.12.14-slim@sha256:f77ac9e44ae96ef2c90b8053ea08c31f8be030f824196b0ae4db6d462c84e51f
COPY --from=build /go/bin/minio /usr/local/bin/minio
ENTRYPOINT ["minio"]

go install 未注入官方发行脚本的 ldflags，因此 minio --version 显示 DEVELOPMENT.GOGET，不能把这个字符串伪称发行二进制版本；源码身份通过 Go 嵌入模块 buildinfo 和锁定模块版本核验。构建输出 digest 与实际版本记录在本包 verification。源码 AGPLv3 许可随服务保留，不能从商业产品许可推断社区源码许可。

首次启动与平台 ​

历史批次验证环境：Windows PowerShell、Node 24.21.0、Docker 29.8.2 Linux 容器。不是 Windows 原生 MinIO 服务验证。以下单行 Docker 命令也适用于 Linux Bash；SDK 程序跨平台运行，但本轮不包括 macOS。命令在仓库根目录执行：

powershell
docker build --pull=false -t showdocs-m4b-minio:2025-10-15 examples/minio
docker run -d --name showdocs-m4b-minio-main -p 127.0.0.1:23000:9000 -v showdocs-m4b-minio-data:/data -e MINIO_ROOT_USER=m4b-local -e MINIO_ROOT_PASSWORD=m4b-local-secret-only showdocs-m4b-minio:2025-10-15 server /data --console-address :9001
npm ci --prefix examples/minio --ignore-scripts --no-audit --no-fund
node --test examples/minio/app.test.mjs

服务只绑定本机 23000，控制台 9001 不映射到主机；学习不依赖控制台 UI。凭据是隔离实验固定值，不应用于真实环境。创建桶/对象的真实 SDK 验收在完整应用运行。名字或卷已存在时先检查，不反复创建覆盖。

桶、对象键与权限 ​

桶名遵守 S3 命名约束，例如 course-objects。对象键 notes/day1.txt 中斜线只是字节名称的一部分，所谓目录是前缀视图。listObjectsV2(bucket, '', true) 递归列出可见当前对象，响应可能分页；SDK 的异步迭代处理分页，不要只取第一页就认为备份完整。

上传对象包含数据与元数据（Content-Type、自定义 metadata）；对象大小、版本 ID、ETag 各有用途。客户端可自选对象键，但映射到本地路径时必须重新设计安全规则，不能直接把远端键拼接到磁盘路径。课程备份将键映射为 SHA-256 文件名，在 manifest 保存原 key。

私有桶默认拒绝匿名读取。根账号用于初始化和本次隔离验收，实际应用应使用限制到具体桶/前缀和动作的身份策略。例如备份通常需要 ListBucket 与 GetObject，恢复需要目标 PutObject，不需要授予全服务管理权。拒绝响应可能是身份、桶策略、签名或时间错误，不能只看“连上端口”判断权限正确。

练习与参考解法 ​

题目：对象键有斜线，是否必须先创建目录？匿名 GET 返回 403，是否说明对象不存在？

提示：区分对象命名、授权判断和对象存在性这三件事。

参考答案与边界

不需要创建目录；直接 putObject 即可。403 表示请求被拒绝，不能据此确定对象存在与否。授权客户端对已知桶读取缺失键通常得到 NoSuchKey，验证器分别验收这两个合同。不要为排错直接把桶设为公开。

MinIO 版本、删除与签名 URL ​

本轮为理论笔记与静态审读，示例、安装命令和验收器均未执行。下文命令用于解释步骤，预期结果不代表本轮实测；“历史验收”仅指此前批次记录。阅读和书面练习不需要启动服务。

版本化对象模型 ​

前置：已启动隔离服务，理解桶和对象键。启用版本控制后，对同一 key 的每次写入生成不同 versionId；未指定 versionId 的读取选择当前版本，指定 versionId 可以读取旧内容。versionId 由服务端生成，不是客户端可递增的业务版本号，也不是对象内容哈希。

维护者 JS SDK 的最小调用如下，放在 examples/minio/ 下的 ESM 文件中，复用完整项目的 client：

js
import { client } from './app.mjs';
const c = client();
await c.makeBucket('course-version-demo');
await c.setBucketVersioning('course-version-demo', { Status: 'Enabled' });
const first = await c.putObject('course-version-demo', 'notes/a.txt', Buffer.from('one'));
await c.putObject('course-version-demo', 'notes/a.txt', Buffer.from('two'));
const stream = await c.getObject('course-version-demo', 'notes/a.txt', { versionId: first.versionId });
for await (const data of stream) process.stdout.write(data);

预期读出 one，默认读取则是 two。示例桶名首次使用，重复执行需要处理已存在桶。启用后只能暂停，不能撤销为从未版本化；暂停状态还涉及 null version，不要把它描述为“清空历史”。版本会增加存储占用，备份和生命周期都必须明确是否处理历史。

删除标记与永久删除 ​

启用版本控制时，不带 versionId 的 removeObject 通常创建 delete marker（删除标记）；默认 GET 随后返回 NoSuchKey，旧版本依然存在。用版本列举才能看到 delete marker 和历史对象；普通列举会隐藏当前删除标记的键。

显式带 versionId 删除某个版本是永久删除该版本，并不会再给那个版本创建删除标记。删除当前 delete marker 可以让之前的版本重新成为可见对象，但不等于恢复了已经永久删除的数据。MinIO 的历史实现对连续删除标记有幂等差异，不应推断所有 S3 实现都相同。

验收器上传两版，删除 key 后断言默认 GET 失败，指定第一版仍读出原字节，再显式删除第一版并确认无法读取。它检查实际 versionId 与 delete marker，不用“文件列表中不见了”代替版本语义证明。

预签名 URL 与权限 ​

预签名 URL 把签名、凭据范围、时间和过期秒数放在查询参数中，让持有 URL 的访问者在授权条件内完成指定动作。它是临时能力凭证，应像密码一样保护，避免日志、聊天与 Referer 泄露。签名包含请求方法、路径、查询及相关请求头；签名后改域名、端口、路径或参数，可能导致 SignatureDoesNotMatch。

js
// 独立保存为 examples/minio/signed-get.mjs；先按上文写入可见对象。
import { client } from './app.mjs';
const c = client();
const url = await c.presignedGetObject('course-version-demo', 'notes/a.txt', 60);
const response = await fetch(url);
if (!response.ok) throw new Error(`HTTP ${response.status}`);
process.stdout.write(Buffer.from(await response.arrayBuffer()));

上例前提是存在可见当前对象；若已经创建删除标记，先重新上传或显式签旧 versionId。有效期 60 秒是 SDK 请求参数，服务端还受签名凭据和时钟影响。URL 到期不等于撤回已下载副本；若要立即撤销还需身份/策略等机制。

历史批次合同记录：有效 URL 返回 200 且逐字节相同，篡改 X-Amz-Signature 返回 403/SignatureDoesNotMatch，匿名读取私有对象返回 403。没有用睡眠等待来验收过期 URL，因此不将“过期后拒绝”列为已测结论。签名参数不保存到版本库证据，只保存状态与错误类别。

练习与参考解法 ​

题目：用户误删对象后，备份工具的普通 ListObjectsV2 为空，能否认定版本历史为空？下载链接 403 时应立刻延长过期时间吗？

提示：先列出当前版本、历史版本、删除标记，再分别检查拒绝请求的签名和权限条件。

参考答案与边界

不能；需按版本列举并区分删除标记。403 也可能是签名改动、权限拒绝或时间漂移，应保留服务错误码和请求 ID，核对原签名条件，延长有效期未必解决问题。禁止在排错输出中打印完整 URL 的凭据参数。

资料：维护者 JS SDK API、S3 删除版本、中文版本控制解释。
