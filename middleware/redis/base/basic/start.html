Redis 起点与命令：隔离服务、连接与键空间 ​

查找 String、Hash、List、Set、Sorted Set 的区别与用途，请阅读 Redis 数据类型。

本轮仅全文静态审计，未安装依赖、启动服务、连接数据库或执行任何示例。下文实测、RED/GREEN及平台结果均为此前历史证据；本轮修改后的脚本未运行，命令与输出作为学习步骤和预期保留。

先理解服务与客户端 ​

Redis 是通过网络接收命令的数据结构服务器。redis-server 管理内存、过期和持久化；redis-cli 是客户端，关闭客户端不会关闭服务。键是字符串，值带类型；同名键不会按类型拥有多个值。端口属于进程，逻辑数据库编号只是键空间分隔，不提供权限或资源隔离。Cluster 仅使用 DB 0，本课程也使用 DB 0。

前置只需要终端和文件路径：在仓库根目录执行命令；examples/redis 是示例源码位置。PowerShell 与 Linux Bash 均可运行下列单行 Docker 命令。Windows 需要 Docker Desktop 的 Linux engine；Linux 需要 Docker Engine。这里实际运行的是 Linux 容器中的 Redis，并非 Windows 原生 Redis。macOS 不列入本批验收。

明确版本与首次启动 ​

Redis 8.2.10 安装到 Linux 容器后，主机通过26379映射端口连接，容器内仍使用6379。下面给出完整拉取、启动和版本确认步骤。

2026-10-17 核对官方 Redis 8.2 发布说明 与 维护者发布记录，采用已有安全修复的 8.2.10 分支补丁，不声称它是最新大版本。客户端与服务器同镜像，避免另装不匹配的 CLI。实际镜像为 redis:8.2.10-alpine，核验摘要 sha256:b51665e66f00759be7c3152ad5ac3c66fb2f619c13ef62dea7cc1f9914524635。部署应固定摘要并跟踪补丁，不能把固定教学版本当永久安全承诺。

sh
docker version
docker pull redis:8.2.10-alpine
docker run -d --name showdocs-m4-redis-main -p 127.0.0.1:26379:6379 -v showdocs-m4-redis-data:/data redis:8.2.10-alpine redis-server --appendonly yes --appendfsync everysec --save ""
docker exec showdocs-m4-redis-main redis-server --version
docker exec showdocs-m4-redis-main redis-cli --version
docker exec showdocs-m4-redis-main redis-cli -e PING

首次启动可能尚未就绪，PING失败时先看日志并等就绪后重试，不要直接删除数据卷。预期版本均为 8.2.10，最后返回 PONG。同名容器已存在时检查 docker inspect showdocs-m4-redis-main，不要再启动第二份。docker start 启动停止的容器；docker logs 查看退出原因。容器内端口 6379，主机端口 26379；映射到回环地址仅供本机实验。远程服务需另行配置网络、ACL、TLS和凭据，本例无生产认证方案。

-v 创建独立实验 volume；删除容器不会自动删除该数据卷。命令中的空 --save 关闭周期 RDB，AOF 保留开启。后面手动快照仍可运行。只操作 showdocs-m4-redis-*，不要连接已有业务实例运行清理命令。

redis-cli 连接、输出与错误退出 ​

以下每行均是完整命令；把最后一条 Redis 命令替换成后续页面示例即可。docker exec 进入容器执行，不通过主机映射端口；宿主机安装官方 CLI 后可改用 redis-cli -h 127.0.0.1 -p 26379。

sh
docker exec showdocs-m4-redis-main redis-cli -e --json SET m4:hello world
docker exec showdocs-m4-redis-main redis-cli -e --json GET m4:hello
docker exec showdocs-m4-redis-main redis-cli -e --json TYPE m4:hello
docker exec showdocs-m4-redis-main redis-cli -e --json INCR m4:hello
docker exec showdocs-m4-redis-main redis-cli -e --json DEL m4:hello

预期依次是 "OK"、"world"、"string"、整数格式错误、1。失败不是网络断开；INCR 要求字符串可解析为整数。-e 让 Redis 命令错误成为非零进程退出；--json 是 CLI 输出编码，不是向 Redis 存入 JSON 数据类型。PowerShell 检查 $LASTEXITCODE，Bash 检查 $?。程序调用用参数数组传递，不把用户输入拼进 shell。

查找键与生命周期 ​

sh
docker exec showdocs-m4-redis-main redis-cli -e SET m4:short hello EX 30 NX
docker exec showdocs-m4-redis-main redis-cli -e TTL m4:short
docker exec showdocs-m4-redis-main redis-cli -e SCAN 0 MATCH m4:* COUNT 20
docker exec showdocs-m4-redis-main redis-cli -e UNLINK m4:short

NX 只在不存在时设置，条件失败返回空。EX 单位秒，PX 单位毫秒。SCAN 首次游标 0，持续用返回游标直到再次为 0；COUNT 是工作量提示，可能空批、重复，遍历期间数据变化也不是一致性快照。对结果去重，避免把 SCAN 当导出工具。KEYS 会一次扫描并阻塞服务，不能为了简单在大实例替代 SCAN。UNLINK 先移除键名，再异步回收大值；客户端仍需控制批量和延迟。

练习与参考解法 ​

提示：把NX条件失败与键过期分开；先核对连接位置再判断值是否缺失。

题目：创建只允许首次写入的 30 秒配置，再重复一次；说明为何第一次返回 OK，第二次为空，TTL 仍在下降。排障：PING 正常但 GET 返回空时，要检查哪些条件？

参考解法

执行 SET m4:exercise value EX 30 NX 两次，随后 TTL m4:exercise。条件失败不覆盖值、不重新计时。GET 空可能是未写入、过期、被删除、连接错误实例或 DB；先检查主机端口、CLIENT INFO、TYPE、TTL，不要直接把空当网络故障。验证完成用 DEL m4:exercise 删除这一个测试键。

完整可复跑命令与结果见验证与运维。本批不覆盖集群部署、Sentinel自动故障转移和通用分布式锁证明。
